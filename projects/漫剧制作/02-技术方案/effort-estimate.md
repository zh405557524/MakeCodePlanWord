## 0. 评估结论

本评估按 **AI 辅助真实开发时间** 估算，不按传统纯人工工期估算。

| 口径 | 结果 |
|------|------|
| 目标范围 | Flutter App + Kotlin 后端 + 登录用户 + 付费权益 + AI 生成主链路 |
| 期望总工时 | 约 49 人天 |
| Flutter 移动端 | 约 14 人天 |
| Kotlin 后端 / AI 任务 / 存储 | 约 25 人天 |
| 登录、用户、付费专项 | 已纳入前后端任务，约 10 人天 |
| QA / 联调 / 支付沙箱 | 约 10 人天 |
| 建议排期 | 4 周冲刺版 |
| 建议团队 | 1 Flutter + 1 Kotlin + 0.5 QA，支付和 AI Provider 资料第 1 天准备好 |
| 单人全栈 + AI 串行 | 约 7 到 9 周 |
| 只做可演示 mock 版 | 约 2.5 到 3.5 周 |

当前技术方案原本写的是“暂不强依赖账号体系，使用 `installation_id` 标识设备”。新增登录和付费后，核心变化是：作品归属从设备级升级为用户级，生成动作要受权益/余额控制，视频生成前后要和付费、扣费、失败退回绑定。

## 1. 评估前提与假设

- 每日有效工时：1 人天 = 8 小时 AI 辅助开发有效工时。
- 团队配置：1 名 Flutter、1 名 Kotlin、0.5 名 QA。
- 最小估算颗粒：0.5 人天，个别 AI 可快速完成的底座任务用 0.3 到 0.8 天表达。
- 前后端可并行；QA 从第 2 周后半段开始介入。
- 登录按手机号验证码 + Token 会话估算；不含微信/Apple/Google 多渠道登录。
- 支付按一个支付渠道最小闭环估算：套餐、下单、回调验签、到账、重复回调幂等、失败补偿。
- 付费模型按“点数/额度/生成次数”权益账本估算，不含复杂会员等级、优惠券、分销、退款后台、发票、财务对账后台。
- AI 生成 Provider 已有可接入服务或 mock adapter 可先跑通；若接入全新未验证模型服务，需额外加 20% 到 40% 风险缓冲。
- 不包含应用商店上架审核周期。

## 2. 新增登录与付费后的范围调整

| 模块 | 原逻辑 | 新逻辑 |
|------|--------|--------|
| 身份边界 | `installation_id` 设备级身份 | 登录用户为主，保留 `installation_id` 用于游客态和设备迁移 |
| 作品归属 | 作品绑定设备 | 作品绑定 `user_id`，游客作品登录后可迁移 |
| 生成限制 | 主要由任务状态限制 | 生成前检查余额/权益，提交任务时冻结或预扣 |
| 付费入口 | 无 | 套餐页、支付结果页、权益余额、订单状态 |
| 后端新增 | 无账号系统 | 用户、验证码、Token、订单、支付回调、权益账本 |
| QA 新增 | 主流程生成测试 | 登录态、游客迁移、支付沙箱、重复回调、扣费退回 |

## 6. 关键路径与并行度分析

关键路径：

1. `T-B014 -> T-B015 -> T-F017 -> T-Q008`  
   登录与付费权益是新增硬链路，支付回调和权益账本不稳定会直接拖延验收。
2. `T-B001 -> T-B004 -> T-B008 -> T-B009 -> T-Q005`  
   文本解析、分镜资源、视频生成决定产品核心价值是否能跑通。
3. `T-F001 -> T-F009 -> T-F013 -> T-F014 -> T-Q001`  
   分镜处理和任务轮询是移动端复杂度最高的部分。

可并行项：

- 登录 UI 可先用 mock 验证，后端验证码和 Token 完成后再接真实接口。
- 套餐页和支付结果页可先接 mock 订单，后端支付回调完成后再换沙箱。
- 角色、场景、分镜 UI 可与后端 AI adapter 并行。
- QA 可在第 2 周开始测页面、登录、mock 主链路，不必等视频生成完全稳定。

主要阻塞：

- 支付商户号、沙箱、回调域名、验签密钥没有在第 1 周准备好，会直接影响 4 周目标。
- AI Provider 的分镜资源和视频合成接口如果需要重新摸索，后端 T-B008 / T-B009 悲观工时会放大。
- 登录后作品归属和游客迁移规则如果产品没定，会影响作品列表、创建作品、订单权益绑定。

## 8. 风险缓冲

本项目建议采用 **内置 20% 缓冲 + 外部依赖任务重点跟踪**。

需要重点跟踪的高风险任务：

- `T-B015` 支付订单、回调验签、权益账本、失败退回。
- `T-Q008` 支付沙箱、重复回调、到账和扣费回归。
- `T-B008 / T-B009` 分镜资源生成与视频生成 Provider 接入。
- `T-F009 / T-F013` 分镜处理页与异步任务轮询。

如果支付资料、短信服务、AI Provider、对象存储任一项在第 1 周无法准备，建议从 4 周调整为 5 到 6 周。

## 10. 待确认项

- [ ] 登录方式是否只做手机号验证码，还是要微信/Apple/Google。
- [ ] 付费模型是点数、生成次数、会员订阅，还是套餐混合。
- [ ] 生成视频扣费时机：提交任务时预扣，还是生成成功后扣费。
- [ ] 失败任务是否自动退回权益，还是允许用户手动重试不重复扣费。
- [ ] 游客作品登录后是否自动迁移到用户账号。
- [ ] 支付渠道、商户号、沙箱、回调域名是否已准备。
- [ ] AI Provider 和对象存储是否已有账号、密钥、测试额度。
