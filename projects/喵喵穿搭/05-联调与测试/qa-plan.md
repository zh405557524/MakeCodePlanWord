### 1.2 状态约定

| 状态 | 含义 |
|------|------|
| `not_run` | 用例已设计，尚未执行 |
| `blocked_by_TBD` | 需求行为或期望值尚未确认，确认后才能执行 |
| `blocked_by_build` | 需求明确，但客户端/接口/测试包尚不可用 |
| `passed` | 在指定环境按步骤执行且实际结果符合期望 |
| `failed` | 实际结果与明确需求或后端契约不一致 |
| `not_applicable` | 经产品、研发、测试共同确认本版本不适用 |

说明：会员商品、价格、有效期、赠送积分和会员状态以后端返回为准；这些字段不再向产品负责人提问，但测试时必须验证客户端没有写死或补造数据。

## 2. 测试范围与边界

### 2.1 本轮覆盖

- P01～P31 共31个逻辑页面/入口及关键状态。
- 登录、协议、用户资料、会员、积分、签到、邀请、订单和支付等共享后端能力的必要回归。
- 档案、衣橱、AI试衣、搭配、发型、彩妆、报告、作品等喵喵穿搭专属业务。
- AI任务的提交、生成中、成功、失败、取消、超时、重试、扣费/返还和结果留存。
- 高敏感照片、身体参数、作品下载/分享/删除、日志脱敏和越权访问。
- iOS/Android、大小屏、系统字体、弱网、断网、前后台切换和重复提交。

### 2.2 不在当前执行范围

- 真实支付渠道、生产部署、生产数据库迁移和应用商店审核。
- 未完成技术方案前的具体接口路径、数据库表和算法指标验收。
- Figma 像素级验收；截图落盘前仅登记检查点，不给出 PASS。
- 25项产品待确认内容的最终期望值；本文只建立对应测试入口。P0-01 已按后端统一100件关闭。

### 2.3 测试层级

| 层级 | 主要责任 | 最低要求 |
|------|----------|----------|
| Flutter 单元/Widget | 页面状态、表单校验、Provider/状态机、响应式布局 | 关键状态有自动化回归；`flutter test` 通过 |
| Java 单元/集成 | 业务规则、权限、事务、幂等、积分批次、支付回调 | 关键 Service 与接口集成测试通过；构建无失败 |
| API 联调 | 请求/响应契约、错误码、超时、重试、并发 | 主链路和异常链路均有证据 |
| E2E | 用户从入口到结果/恢复的完整行为 | P0主链路全通过 |
| 人工专项 | UI、真机、支付、隐私、弱网、前后台 | 设备/环境/账号可追溯 |
