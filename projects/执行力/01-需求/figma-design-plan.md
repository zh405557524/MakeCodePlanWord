## 1. 文档目的与适用范围

本文档用于把当前版本需要补齐和维护的 Figma 设计范围整理成可执行清单，避免后续编码只凭零散截图猜界面。

适用范围：

- 当前版本移动端 MVP
- `Now / Chat / Plan / Notes / Profile` 五个一级入口
- `BattleMap / TrackDetail / PlanEditor / UserProfile / NoteFolder / NoteFile` 等二级页
- 与页面直接相关的关键弹层、空态、状态卡、底部导航和通用组件

本文档不是 PRD，也不是开发计划；它服务于“设计稿补齐、对照、复核和后续代码实现”。

## 2. 设计目标与视觉方向

### 2.1 设计目标

- 让用户在首屏就理解“现在该做什么、计划从哪看、笔记从哪记”。
- 保持产品核心气质：轻执行压力、强结构感、品牌感明确。
- 让 `Plan` 与 `Notes` 在导航层级上同等清晰，不把 Notes 误做成计划子功能。

### 2.2 视觉方向

- 整体仍采用轻浅底色 + 品牌紫蓝渐变作为视觉主轴。
- `Chat` 和部分 Hero 区使用更强沉浸感的深色 / 渐变背景。
- `Notes` 页应比 `Plan` 更克制、更偏信息组织，不做强烈作战感。
- 文件夹与文件在视觉上必须明确区分，避免混淆信息层级。

### 2.3 Notes 设计补充方向

- `Notes` 首页：强调创建文件夹 / 创建笔记两个高频动作。
- `NoteFolder`：强调路径感和层级上下文。
- `NoteFile`：强调标题、路径、编辑 / 预览切换和正文可读性。

## 6. 组件与设计 Token 清单

### 6.1 组件清单

- 底部导航栏
- 顶部 Hero 卡
- 一级操作按钮
- 白卡 / 信息卡 / 指标卡
- 时间线卡
- 聊天气泡
- 输入栏
- 文件夹列表项
- 文件列表项
- 编辑 / 预览切换按钮
- 固定底部 CTA

### 6.2 Token 清单

- 颜色：沿用 `执行力-颜色文档-v1.1.md`
- 字号：标题、正文、标签、说明文
- 间距：8 / 12 / 16 / 20 / 24 / 32 级别
- 圆角：按钮、小卡、大卡
- 阴影：浅色卡与品牌卡分开定义
- 渐变：Splash、品牌按钮、Plan Hero、Track Hero
- 图标风格：线性为主，Notes 模块允许用简洁文件夹 / 文件图标增强识别

### 6.3 Notes Token 补充

- 文件夹图标强调暖色系识别
- 文件图标强调品牌色识别
- 文件页正文区域优先可读性，不追求花哨背景

## 7. 交互 / 原型清单

必须补齐或验证的交互原型：

- Splash 自动跳转到 MainShell
- Chat 进入全屏、返回主壳
- Plan Hero 进入 BattleMap
- TrackDetail 返回 BattleMap，CTA 进入 Now
- PlanEditor 保存后回到来源页
- Profile 进入 UserProfile，再回写 Profile
- Notes 首页进入 NoteFolder
- NoteFolder 继续进入下一层文件夹
- NoteFolder 进入 NoteFile
- NoteFile 在编辑 / 预览间切换

对原型演示的最低要求：

- 至少覆盖一条完整主链路：`Plan -> BattleMap -> TrackDetail -> Now`
- 至少覆盖一条 Notes 链路：`Notes -> NoteFolder -> NoteFile`

---

## 8. 设计验收标准

- 所有当前版本页面都能在 Figma 中找到唯一对应 frame 或明确的多视觉态关系。
- 5 个一级入口都可在设计稿中清晰识别：`Now / Chat / Plan / Notes / Profile`。
- `TrackDetail` 与 `PlanEditor` 保持“单页骨架 + 多视觉态”设计，不拆成无关页面。
- `Notes` 的三张页面能清楚表达“根目录 -> 子文件夹 -> 文件内容”的层级关系。
- 设计稿与 PRD 冲突时，以当前版本 PRD 为准，并同步回写设计计划。

## 9. 待确认项

- `Notes` 是否需要在当前版本就支持“从 Plan 挂笔记 / 从笔记生成计划”，当前默认不做。
- `NoteFile` 当前只要求普通文档与 Markdown 编辑 / 预览，是否需要工具栏，默认后置。
- 若后续出现 PC 版或知识整理模块，是否沿用当前 `Notes` 信息架构继续扩展，暂不在本轮展开。
