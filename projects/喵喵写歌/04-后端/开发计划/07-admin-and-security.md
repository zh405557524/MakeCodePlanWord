# Admin 配置与资源安全配套

> `v2.1-model-driven-params` · CHG-0076 · 第 12 步 · 文档 `waiting_review`。配套 `T-B002-S/R`、`T-B006-S/R`，与[Web W001/W002](../../03-前端/开发计划/06-admin-capabilities.md)和[当前 PRD P14](../../01-需求/v2.1-model-driven-params/requirements.md)对齐；不另建独立计费/审核体系。

## 骨架阶段 / `T-B002-S`、`T-B006-S` 配套

- 只对现有 `/api/admin/ai-scene-model-mappings`、模型/价格/音色/任务/作品管理 Controller → Service 的配置调用链加可读的“加载厂家能力 → 校验管理员与 App → 验证合法子集 → 预览/保存”步骤。Admin 前端的模型能力面板只显示受控 Fixture 的确定配置，并清楚标注 local/test。
- 继续用现有 Admin token、角色管理块与 `X-App-Code`；只有 `catsinger` 可读写本业务配置，非超级管理员需要所属管理块权限。骨架不得落库、审核真实资源、启用真实模型或改变线上配置；生产不暴露假能力。
- 契约测试覆盖角色拒绝、App 切换和扩大厂家能力被拒的调用路径；正式保存逻辑待 `-R`，写 `TODO(REAL-IMPLEMENTATION)`。

## 真实实现阶段 / `T-B002-R`、`T-B006-R` 配套

1. 后台只允许对 B001 厂家**明确声明**的能力做收窄：展示/启用、选项子集、范围子区间、默认值和价格。不能用 `metadataJson` 或旧配置开放未声明参数，不能在 `NOT_DECLARED` 状态下伪造完整能力；提交时服务端重新求交集，不信 Admin UI 的禁用态。
2. 模型/价格更新形成可追溯的 `contractVersion` 与独立 `pricingVersion`，给新任务生效；旧任务保持创建时快照。模型下架只阻止新任务，历史作品/已开始任务按既有规则；默认模型要确保在业务场景里确实可用。
3. 官方音色名称/头像由后台管理，试听资源来自已审核的厂家或既有资源链路；文字、图片、音频等展示资源沿当前安全审核和隔离逻辑，不额外创建平行审核系统。资源地址不在公开模型目录泄漏管理端内部字段。
4. 超级管理员可分配 App 管理块，其他管理员只操作获授权的 `catsinger` 配置；跨 App 读写由后端再次校验，不以页面隐藏作权限保证。配置变更留现有审计记录，敏感 Provider 密钥不写到公开响应。

## 接口、数据与测试

复用现有 Admin API 命名和场景映射/模型配置/计费配置/音色配置/管理角色表；新字段首先检查现有 `metadata_json` 是否能安全表达，无法表达再在 `T-B006-R` 证据下追加 catsinger 范围迁移。骨架不新增表。验证：厂家能力边界保存成功、范围/默认值越界拒绝、未知能力不能强开、价格改变不改历史任务、普通角色越权、`X-App-Code` 切换不串、未审核试听资源不可公开及旧 Admin 页面兼容。跨业务回归覆盖写歌、改编、训练、克隆四场景的模型目录。
