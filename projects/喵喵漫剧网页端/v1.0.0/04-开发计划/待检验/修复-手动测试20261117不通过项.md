### W-02 资产库“作品资产”灰屏

- 对应：H-01、E-10、L-05
- 原因（高度确定，先用调试模式确认报错）：`lib/pages/assets/view.dart` 第 175 行
  ```dart
  coverUrl: urls[controller.projects[group.originProjectId]?.cover?.resourceId],
  ```
  `urls` 是 GetX 的 `RxMap<String, String>`，它的 `[]` 会把键强转成 `String`。作品没有封面或作品已删除时键是 `null`，强转抛异常，整个 `Obx` 画不出来，发布模式下显示成灰块。别的页面都是先判空再取（例如 `lib/pages/works/view.dart` 第 55 行）。
- 做法：
  1. 第 175 行改成先取出编号、为空就传 `null`：
     ```dart
     final coverId = controller.projects[group.originProjectId]?.cover?.resourceId;
     // …
     coverUrl: coverId == null ? null : urls[coverId],
     ```
  2. 同样的写法还有 `lib/pages/home/widgets/case_masonry.dart` 第 56 行（`controller.mediaUrls[item.cover?.resourceId]`），一并改成先判空。
  3. 全仓库再搜一遍“用可能为空的值直接当 `RxMap` 的键”的写法（搜 `?.resourceId]`、`?.id]`），有就同样处理，并列在交付报告里。
- 验证：调试模式下点“作品资产”，控制台没有异常；有封面、没封面、来源作品已删除的分组都能显示；深色、浅色各看一次。给 `test/pages/` 加一个用例：分组的来源作品没有封面时页面能画出来（不抛异常）。
- 完成标准：作品资产列表正常显示，能点进作品看素材。

### W-03 片段生成完了，等待页不自动更新

- 对应：F-02、D-15
- 原因（已确认）：`lib/pages/storyboard/controller.dart` 的 `_scheduleEpisodePoll`（约第 339～354 行）：
  ```dart
  final latest = await refreshEpisode();
  if (_closed || latest == null || latest.id != before) return;
  ```
  `refreshEpisode()` 只要有一次请求失败（网络抖动、标签页切到后台被浏览器限流）就返回 `null`，这里直接 `return`，没有再排下一次，定时查询从此停掉，页面永远停在等待。
- 做法：把三种情况分开：
  - `_closed`，或用户已经切到别的集（`episodeId.value != before`）→ 停止，不再排。
  - `latest == null`（这一次没查到）→ **再排下一次** `_scheduleEpisodePoll()`，然后 `return`。
  - 其余按原逻辑。
  同文件 `_scheduleShotsPoll` 检查同类问题：`_loadShots(fromPoll: true)` 失败或结果被丢弃后，只要还有生成中的片段就要继续排下一次；没有问题就不改。
- 验证：`test/pages/storyboard_poll_guard_test.dart` 加用例：“一次刷新失败后仍然继续查询，下一次成功且已生成完 → 进入片段列表”。本机实测：进入分镜页等待时，把标签页切走 1 分钟以上再切回，片段生成完后页面自动出现片段列表，不用手动刷新。
- 完成标准：不刷新也能从等待页自动进入片段列表。

### W-05 没确认的“批量生成提示词”结果，回来后要有“待核对”入口

- 对应：F-07
- 原因（已确认）：`problem_banner.dart` 用 `episode.pendingDiffJobId` 判断有没有待核对的结果，它来自后端剧集的 `stageSummary.blockers` 里的 `ANALYSIS_DIFF_PENDING`。但后端只在“这一集还没有生效的片段”时才给这个阻塞项（`DramaEpisodeStageService`）；已经有片段的集再批量生成，结果是待确认状态，却不会出现这个阻塞项，所以网页不知道有东西待核对。
- 做法（只改网页，用已有的查询接口）：
  1. `StoryboardController` 加一个状态 `final pendingDiff = false.obs;`，和一个方法 `_checkPendingDiff(DramaEpisodeBrief episode)`：
     - 取 `jobId = episode.pendingDiffJobId ?? episode.shotGeneration?.jobId`；为空 → `pendingDiff.value = false`。
     - `DramaJobsAPI.get(jobId)` → 取 `job.result?.id`（分析编号）；为空 → `false`。
     - `DramaAnalysesAPI.get(分析编号)` → `pendingDiff.value = analysis.isCandidate`。
     - 请求失败只记日志，不弹提示，`pendingDiff` 保持原值。结果回来时如果已经切到别的集，丢弃。
  2. 调用时机：`_enterEpisode` 里这一集不在生成中时（读完片段后调，不等它）；批量生成提示词弹出的差异窗口**关掉但没点确认**后置为 `true`；点了确认并应用成功后置为 `false`；切集时先置 `false`。
  3. `problem_banner.dart`：`pending` 改成 `episode?.pendingDiffJobId != null || controller.pendingDiff.value`。“去核对”仍调 `openPendingDiff`（它已经会用 `shotGeneration.jobId` 兜底）。
  4. 顺带核对测试里提到的“回来后一度显示本集暂无片段”：复现一次，如果是切集时先清空列表造成的短暂空白，改成读取中显示加载状态而不是“暂无片段”；复现不出来就在交付报告里写明。
- **停下报告的情况**：实测发现待确认结果对应的任务编号不是 `shotGeneration.jobId`（也就是网页没有任何办法找到这份结果），记录剧集接口和任务接口的实际返回，停下报告——这需要后端补字段，不在本计划内。

### W-06 单个片段“生成提示词”确认覆盖后报“内容已更新”（先复现）

- 对应：F-05
- 现象：片段的提示词手改过 → 点“生成提示词”→ 后端返回 `-560017`（会替换手改内容，请确认）→ 用户确认 → 第二次提交返回 `-560001`“内容已更新，请核对最新版本”，没有重新生成。没手改过的片段正常。
- 推断的原因：`lib/pages/storyboard/logic/generation.dart` 的 `describeShot`，第二次提交用的还是第一次的 `shot.revision`。如果第一次请求或中间的自动保存让片段版本号变了，第二次就对不上。
- 做法：
  1. **先复现**：手改一个片段的提示词，等自动保存完成，点“生成提示词”并确认覆盖。在网络面板记下两次 `description-jobs`（或该接口的实际路径）请求体里的版本号，以及紧接着读片段列表得到的该片段版本号。把三个数写进交付报告。
  2. 如果确实是版本号过时：用户确认覆盖后，先 `await _loadShots(shot.episodeId)` 读最新片段，用最新的 `revision` 再提交（带 `overwriteConfirmed: true`）；读完发现片段不在了就提示并结束。
  3. 如果版本号是对的、后端仍返回 `-560001`：记录请求体和返回，**停下报告**（可能是后端判断问题，不在本计划内）。
- 验证：手改过的片段点“生成提示词”→ 确认覆盖 → 任务成功，只有这个片段的提示词变化，不扣积分。给这个流程加一个单元测试（用现有的假数据方式模拟“第一次 -560017、确认后成功”）。
- 完成标准：同上，或按第 3 步给出停下报告的证据。
