## 1. 功能定位与边界

定义代码完成、视觉完成、联调完成和产品验收之间的门槛。该模块不以增加功能为目标，发现契约或需求问题时登记新 CHG。

## 2. 代码级验证

App 与 Admin 分别执行：

```bash
dart format <本次修改的 Dart 文件>
flutter analyze
flutter test
git diff --check
```

先跑受影响测试；共享播放器、资源服务、登录/会员或 Admin Repository 改动时扩大回归。测试失败必须区分本次回归和既有基线，不能删测试换通过。

## 5. Admin 验证

- catsinger App 切换和其他 App 隔离。
- 角色权限、只读/编辑/发布/审核/恢复。
- 模型、场景、选项和训练/翻唱价格。
- 官方/本人音色、训练任务、审核、作品、资源和审计。
- 浏览器目标尺寸下表格、抽屉、弹窗、分页、错误和 loading。

## 6. 真实业务验收

以下均不可用 Mock 替代：

1. 本人音色训练完成，模型/配置/试听由平台持久化。
2. 试听真实开始播放且进度增长。
3. 本人音色完成一首翻唱作品。
4. 官方音色完成一首翻唱作品。
5. 两首作品均在现有播放器真实播放并可下载正确格式。
6. 积分冻结、成功扣减、失败释放与流水一致。

## 7. 回归范围

- AI 写歌、AI 改编的首页入口、创建、任务、作品类型、播放器和计费。
- 登录、会员、积分、资源上传、作品列表和播放器。
- Admin 其他 App、原模型场景、原作品和资源管理。

## 8. 测试执行步骤

1. 按 01-13 模块顺序先运行受影响定向测试，修复本次变更引入的失败。
2. App 与 Admin 分别运行格式化、`flutter analyze`、`flutter test` 和 `git diff --check`。
3. 按 P01-P12 完成 375x812 主尺寸截图，并抽查 390x844、414x896。
4. 在 Android 真机和可用的 iOS 真机/模拟器执行入口、素材、训练、翻唱、作品和播放器流程。
5. 在浏览器完成 catsinger Admin 的配置、审核、任务、作品、资源、权限和跨 App 隔离验证。
6. 在测试环境完成真实本人音色训练、本人/官方音色翻唱、积分和成品播放闭环。
7. 回归 AI 写歌、AI 改编和共享播放器，汇总证据后再决定 PASS、FAIL、BLOCKED 或 NOT_RUN。

## 9. 证据与结果

每条测试记录平台、版本、设备、账号类型、配置快照、taskId/workId、结果 PASS/FAIL/BLOCKED/NOT_RUN、截图/UI XML或浏览器截图和失败原因。任务成功但无法播放必须 FAIL。

## 10. 验收标准

- 定向测试、全量受影响测试、analyze 和 diff 检查通过。
- 38 个视觉状态均有证据或明确复用说明。
- Android/iOS/Admin 核心用户流程均执行。
- 高风险付费、删除和发布动作使用测试环境和独立授权。
- 旧 AI 写歌/AI 改编没有行为回归。

## 11. 编码注意事项

代码级通过不自动把模块标记为产品验收通过。厂家账号、余额、模型配置、审核服务或设备缺失时如实标为 BLOCKED，不用本地假数据补成 PASS。
