# T-09 草稿冲突确认保护

2026-10-19；App dev `13f76ca`，已提交未推送。产品/API/数据库/原生引擎不变。

## 问题及修复

输入、故事、逐集剧本的冲突弹框原先仅返回保留本机/采用云端的布尔选择，没有传递用户实际核对的快照。弹框打开后本机或远端内容变化，旧确认仍可能处理当前新稿；旧实现四个回归全部失败，见[失败记录](regression-before.txt)（仅去行尾空白，原始日志摘要见verification.json）。

现在三个View把打开弹框时的DraftSnapshot传回Controller，再由唯一DraftSyncService核对当前作用域、同一已发布快照、当前冲突和可写状态；刷新在途同样拒绝。旧核对失效时保留双方最新稿、无新PUT，并提示重新核对；重新打开后可正常选择，重复旧确认不再写。账号/环境/实际后端变化后拒绝旧选择，不抛失效草稿异常。

修复还覆盖已知冲突的刷新：保留的旧saveIntent/createIntent不再阻止GET最新稿。保存未知且尚未确认冲突的原请求恢复规则不变。服务端CAS继续保护确认后才发生的远端变化。
