## 1. 文档用途

本文档把 Flutter 技术方案拆成可执行、可暂停、可恢复的总体开发计划，供后续生成模块开发文档和执行编码使用。

- 明确移动端和运营后台的功能顺序、依赖、UI 前置和验收结果。

- 记录当前恢复点，避免中断后重复分析或跳过任务。

本计划不负责：

- 不直接修改 catseller 或 lxwx_admin 代码。
- 不生成模块级详细编码步骤；模块细节在下一阶段输出。
- 不扩大已确认产品范围，不把页面内部元素拆成新的页面任务。

任务编号仅用于技术追踪和恢复。日常沟通与验收优先使用“首页、填写信息、作品、视频生成”等业务名称。

## 4. 总体开发策略

### 4.1 移动端

按现有 `GetX + go_router + Dio + GetStorage/Hive + Global.init() + CustomScaffold` 技术路线实施：

1. 先清理用户路径中的写歌业务入口，稳定“首页、作品、我的”三个 Tab。
2. 再建立带货 Model、API、Store、路由和统一状态组件。
3. 打通首图上传建草稿、填写信息、AI 帮写和带货形象。
4. 完成作品列表及按最新状态进入对应业务页面。
5. 完成内容生成、编辑脚本、分镜图片和历史版本。
6. 完成视频报价、积分确认、视频生成、失败和完成页面。
7. 最后完成前端 AI 水印导出、下载分享、公共页面复用和真机回归。

### 4.2 运营后台

运营后台在 `lxwx_admin` 中实施：

1. 注册 catseller App 和菜单权限。
2. 接入案例管理、业务/计费配置和 AI 模型配置。
3. 接入作品与任务查询。
4. 完成 App 切换、权限、数据隔离和其他 App 回归。

### 4.3 并行方式

- Flutter 开发 A：主攻移动端主链路、作品状态和视频完成。
- Flutter 开发 B：主攻基础模型/API、形象、公共复用、运营后台，并按依赖支援主链路。
- 两人共用同一接口模型与状态枚举，禁止各自建立平行数据结构。
- UI 未交图时先完成 API、Model、Controller 和状态骨架；对应页面正式验收仍以最新 UI 交图为准。

## 8. API 与本地逻辑依赖表

| 前端业务 | 后端接口 / 本地逻辑 | 前端处理 |
|----------|--------------------|----------|
| 首页 | `GET /api/catseller/home`、`GET /api/catseller/config` | 游客可读；失败保留主入口并展示可重试状态 |
| 更多案例 | `GET /api/catseller/cases`、`GET /api/catseller/cases/{caseId}` | 二级页登录；无筛选游标分页；AI 案例显示水印 |
| 商品图片 | 公共资源直传接口、`POST /api/catseller/works` | 1～3 张；每图独立进度；首图成功后创建草稿；失败项可单独重试 |
| 填写信息 | `PATCH /api/catseller/works/{workId}/input`、`POST .../content-tasks` | 保存描述、比例、时长、形象和版本；提交后按作品状态恢复 |
| AI 帮写 | `POST/GET /api/catseller/description-tasks...` | 轮询任务；点击使用才覆盖描述 |
| 带货形象 | `/api/catseller/personas`、`/api/catseller/persona-tasks` | 处理选择、上传、定制、重命名、删除影响和 AI 水印 |
| 作品 | `GET /api/catseller/works`、`GET /api/catseller/works/{workId}` | 列表只作摘要；点击后以聚合详情决定页面 |
| 脚本和镜头 | 脚本版本、镜头编辑、图片历史、当前图片、失败镜头接口 | 使用乐观锁；冲突时刷新；口播可空，画面必填 |
| 视频报价 | `POST .../video-quotes` | 不在本地决定最终总价；报价变化后重新确认 |
| 视频任务 | `POST .../video-tasks`、`POST .../video-tasks/retry` | 幂等提交；运行中不可取消；使用服务端轮询间隔 |
| 视频结果 | `GET /api/catseller/works/{workId}/video` | 播放短期资源；AI 视频导出带水印本地文件 |
| 本地草稿 | GetStorage/Hive | 保存表单值、resourceId 和顺序；不保存永久 URL，不代表服务端成功 |
| 登录与复用 | 现有 Auth、User、Points、Payment、Task、Redeem、Invite 接口 | 沿用当前 Dio/JWT/Token 刷新和支付恢复逻辑 |

所有创建、提交、重生成和恢复操作携带 `Idempotency-Key`。运行中详情使用服务端 `nextPollAfterMs`，离开页面、进入后台或达到终态后停止轮询。

## 11. 编码约束

- 移动端实现真源是 `/Users/soul/code/lxwx/catseller`，不是 Catsinger 工程。
- 运营后台只修改 `/Users/soul/code/lxwx/lxwx_admin`；保留用户已有 `web/index.html` 修改。
- 不引入 Riverpod、Provider、Drift 或第二套路由/网络框架。
- 新页面沿用 `index.dart + controller.dart + view.dart`，大 Widget 只在所属页面内拆分。
- 页面内部的图片上传、预览、参数和弹框不建立独立业务页面任务。
- 用户路径不得继续出现写歌入口、歌曲作品或音频播放器；公共登录、支付、积分依赖未解除前不得盲删旧文件。
- 所有请求继续携带 `X-App-Code: catseller`；私有接口使用现有 Token 注入和刷新。
- 运行中任务无取消入口，弱网请求失败不能改写任务终态。
- 视频报价只认服务端结果；充值返回后重新获取余额和报价。
- `aiGenerated=true` 的图片、形象和视频必须在预览和本地导出中显示水印。
- Figma 已跳过；实现依据依次为确认文档、UI 最新交图、原始参考图、旧工程页面。
- 更多案例作为最后一个新增页面完成；UI 定稿后不接受非阻塞视觉扩张。
