## 1. 为什么手机能传、网页不能

手机 App 拿到后端签发的上传地址后，直接把文件 PUT 到存储桶，存储桶只核对签名。浏览器多一道安全检查：网页和存储桶不在同一个域名，浏览器会先发一个预检请求（OPTIONS）问存储桶“这个网站能不能 PUT”。存储桶没有对应规则就回 403，浏览器直接拦住，不发真正的上传。

## 2. 要改哪个桶

本机、测试、正式三套后端用的都是同一个桶：**`lxwx-music`（华南 1 深圳，`oss-cn-shenzhen.aliyuncs.com`）**。依据：后端 `application.yml` 默认值，以及 `config/runtime/deploy-backups/config-sync-20261103T101935Z-jtgt6698/` 里测试、正式两份运行配置的 `ALIYUN_OSS_BUCKET`。所以只要加一条规则，三个环境都能用。

## 3. 第 1 步（用户，在阿里云控制台操作）

1. 登录阿里云 OSS 控制台 → 存储桶列表 → 打开 `lxwx-music`。
2. 左侧菜单“数据安全”→“跨域设置”。
3. **先看一眼已有的规则，不要修改或删除**：这个桶喵喵写歌、其他 App 也在用，已有规则可能是别处在用的。
4. 点“创建规则”，按下表填写后保存：

| 项 | 填写 |
|---|---|
| 来源 | 每行一个，共 4 行：<br>`http://localhost:*`<br>`http://127.0.0.1:*`<br>`https://test.lxwanxiang.com`<br>`https://www.lxwanxiang.com` |
| 允许 Methods | 勾选 `PUT`、`POST`、`HEAD` |
| 允许 Headers | `*` |
| 暴露 Headers | `ETag`<br>`x-oss-request-id` |
| 缓存时间（秒） | `600` |
| 返回 Vary: Origin（有这个选项就勾上） | 勾选 |

5. 保存后等 1～2 分钟生效。

注意：
- 来源**不要只填一个 `*`**。按上表列具体地址，只放行自己的网页。
- 不要用 `ossutil cors` 之类的命令行改：那类命令是整体覆盖，会把桶上已有的规则全部删掉。
- 安全上没有放松：上传仍然需要后端签发的临时签名地址，没有票据传不上去。
- 网页正式地址是 `https://www.lxwanxiang.com/studio/`、测试地址是 `https://test.lxwanxiang.com/studio/`（开发计划 T-02），来源只认域名，不带 `/studio/`。以后网页换域名，或者换存储桶，要回来加一条。

做完后告诉 Claude 或直接把第 2 步交给 Codex。

## 4. 第 2 步（Codex，用户做完第 1 步后执行）

执行方式：一口气做完。不改任何代码；只有“预检仍然失败”时停下报告。

### V-01 核对预检

在用户的电脑终端里执行（不需要密钥）：

```bash
for o in http://localhost:5173 https://test.lxwanxiang.com https://www.lxwanxiang.com; do
  echo "== $o"
  curl -s -o /dev/null -D - -X OPTIONS \
    "https://lxwx-music.oss-cn-shenzhen.aliyuncs.com/private/catdrama/cors-check.png" \
    -H "Origin: $o" \
    -H "Access-Control-Request-Method: PUT" \
    -H "Access-Control-Request-Headers: content-type" \
    | grep -i "^HTTP\|access-control"
done
```

- 预期：三个来源都返回 `HTTP/1.1 200`，并带 `Access-Control-Allow-Origin: <对应来源>`、`Access-Control-Allow-Methods` 含 `PUT`。
- 任何一个不是 200：把完整输出贴进交付报告，**停下报告**（多半是规则没保存、来源写错，或改到了别的桶）。

### V-02 浏览器里走一遍所有直传入口
