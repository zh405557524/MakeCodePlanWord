- 具体做法：
  1. 打开时 `GET /api/products?type=POINTS&page=1&pageSize=20`，默认选中第二档（无第二档选第一档）。
  2. 选中套餐时按下面顺序找订单，**同一次弹窗里同一个套餐只下一单**：① 本次弹窗已经为这个套餐下过单且没过期 → 直接显示它的二维码（需要时调 `POST …/pay-params` 重新取表单）；② 打开弹窗时查一次 `GET /api/payments/orders?page=1&pageSize=20`，有这个套餐的待支付且没过期的订单 → 用 `pay-params` 接着用它；③ 都没有 → `POST /api/payments/orders`（`productType=POINTS`、`channel=alipay_web`；`Idempotency-Key` 每个“弹窗 + 套餐”固定一个，重试用同一个）。把 `payParams.formHtml` 放进 iframe。快速连续切换套餐时，只处理最后一次选择（300 毫秒内的切换不下单）。
  3. 轮询：**本次弹窗里用过的每一笔订单都查**（`GET /api/payments/orders/{orderNo}`，前 2 分钟每 3 秒，之后每 10 秒），切换套餐时不取消旧单、也不停止查它——用户可能已经扫了旧二维码。任何一笔变成 `PAID` → 立刻盖掉二维码小框（支付宝会把小框跳到返回地址）、显示成功态（显示到账的那一笔的套餐和积分）、调 `auth_store.refreshProfile()`、停止全部轮询。查询请求连续失败 3 次 → 显示“支付确认中”（§4 第 13 行），继续按 10 秒一次查，恢复后回到原状态。
  4. 过期判断：后端返回的 `expiresAt` 是不带时区的北京时间，**解析时固定按 +08:00**，再和当前时间比（不要按浏览器本地时区解析，否则不在北京时间的电脑上会差十几个小时）；查到订单状态是 `CLOSED` 或接口返回 `-3001` 也算过期，以后端为准。当前显示的订单过期 → 显示“二维码已失效”。
  5. “刷新二维码”：给同一个套餐新下一单（新的 `Idempotency-Key`），旧单已过期关闭。
  6. 关闭弹窗即停止轮询；不取消订单。`RechargeDialog.show(context)` 返回这次有没有到账（`true` / `false`），调用方据此刷新积分；到账后只关闭弹窗回到原页面，不替用户提交任何操作（AC-04-6）。
  7. `resumeOrderNo` 不为空时（来自我的订单“继续支付”）直接调 `pay-params`，不新下单，选中该订单的套餐；返回 `-3001` → 提示“订单已过期”，按第 2 步重新开始。
  8. 付款区链接：“查看积分规则”→ `/docs/payment-policy`（积分规则 = 积分充值协议，用户 2026-11-16 同意）；“联系客服”→ 新标签页打开 `legalPageUrls['customer-service']`；“《喵喵漫剧付费服务协议》”→ `/docs/payment-policy`。
