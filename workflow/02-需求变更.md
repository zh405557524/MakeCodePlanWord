# 02 需求变更（changes.md）

目标：写清这一版对基线做了哪些"增 / 改 / 删"，每一条都带可验证的验收标准。验收标准就是后面测试用例的来源。

## 输入

- `scope.md`（范围）
- `doc/product/` 中涉及模块的基线文件（现状）
- 用户提供的需求材料、截图、参考稿

## changes.md 的结构

按**模块**组织，模块名和 `doc/product/` 的文件对应。这样发布时合并回基线就是逐模块搬运。

```markdown
## 模块：会员支付（基线：product/membership-payment.md）

### R-03 [修改] 订单记录商店实际扣款币种
- 基线现状：§3.2 订单字段只有金额，没有币种
- 改为：订单保存商店回执中的币种和实付金额；订单列表按订单币种显示
- 原因：线上欧盟、南美用户订单显示成美元
- 验收标准：
  - AC-03-1：巴西区账号购买年卡 → 订单 currency=BRL，amount=商店实付金额；订单列表显示 "R$ xx,xx"
  - AC-03-2：美国区账号购买 → currency=USD，金额与商店一致
  - AC-03-3：商店回执缺少币种 → 订单标记异常并记录日志，不默认写 USD
- 来源：用户确认 2026-10-08
- 调整记录：
  - （开发中修改时追加：日期 + 改了什么）
```

条目规则：

- 编号 `R-序号`，在本版本内递增，不复用。类型只有 `[新增]` `[修改]` `[删除]` `[取消]`（`[取消]` 表示本版原计划要做、后来不做了）。
- `[修改]` 和 `[删除]` 必须写"基线现状"，指明改的是基线哪一节。
- **每条都要有验收标准**，编号 `AC-条目号-序号`。验收标准要写到可以判断对错的程度：
  - 涉及钱、账号、权益、同步的，**必须写数据结果**（存了什么、接口返回什么、后台显示什么），不能只写页面上看到什么。
  - 涉及多地区、多语言、多设备的，写出要覆盖哪些组合。
  - 写失败和边界情况，不只写成功路径。
- 新页面用下面的「页面模板」写在条目里。

## 页面模板（新增页面或大改页面时用）

- 页面定位：这个页面解决什么问题、从哪里进来
- 参考素材：设计稿链接或图片路径；没有就写"暂无设计稿"
- 页面结构：从上到下列区块
- 区块说明：每个区块的位置、内容、交互、反馈
- 交互流程：用 Mermaid `flowchart TD`，节点写用户可感知的步骤
- 状态与异常：加载、空、错误、无权限、离线、超长内容
- 验收标准：AC 列表

## 待确认决策

`changes.md` 顶部有「待确认决策」表，记录需要用户拍板的事：

| ID | 问题 | 当前假设 | 风险 | 状态 |
|---|---|---|---|---|
| D-01 | 退款后会员是否立即失效？ | 立即失效 | 高（资金） | 待确认 |

- AI 推导出来、没有材料依据、也没被用户确认过的规则，在条目里标 `⚠️ 推导，待确认`，并登记到这张表。
- 区分清楚：材料里写过 ≠ 用户确认过；用户说"下一步" ≠ 确认了所有默认值。
- 高风险（资金、账号、权益、数据安全、核心流程）的待确认项没有关闭前，不进入 ④ 开发计划。
- 用户确认后，状态改成"已确认 + 日期"，并把条目里的 `⚠️` 去掉。

## 设计稿数字和运行时数值

价格、积分、次数、时长、额度、有效期这类可能由后台配置、商店或服务端决定的值：

- 写清数据来源（商店 / 后台配置 / 服务端计算）、刷新时机、加载失败时显示什么。
- 设计稿上的数字只说明排版，不能当成业务规则写死。
- 稿子上的数字和接口返回值不一样，不算需求冲突。

## 自检清单（写完逐项过）

- [ ] 每条都有验收标准，钱、账号、权益、同步类的验收标准写到了数据层
- [ ] 失败、空、离线、无权限、重复操作写了
- [ ] 多地区 / 多币种 / 多语言 / 时区的影响写了（如果涉及）
- [ ] 动态数值写了来源，没有把示例值写死
- [ ] `[修改]` `[删除]` 指明了基线位置
- [ ] AI 推导的规则都标了 `⚠️` 并进了待确认表
- [ ] 对照 `scope.md` 勾选的高风险领域，`risk-checklist.md` 里对应的维度都考虑到了

## 新项目（v1.0.0）

没有基线，所有条目都是 `[新增]`。仍然按模块组织，并额外写 `00-overview` 一节（产品定位、目标用户和地区、付费模式、全局规则、模块清单、页面地图），发布时直接成为 `doc/product/00-overview.md`。

## 开发中改需求

直接改对应条目，在"调整记录"追加一行，然后按 `04-开发计划.md` 第 7 节同步计划。不需要新建变更单，也不需要归档旧内容（git 里有历史）。
