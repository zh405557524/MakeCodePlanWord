# 任务命令速查

> 要写计划、改任务状态、改模块进度时读这一份，照着运行。完整规定在 `/Users/soul/work/MakeCodePlanWord/workflow/05-开发.md` 第 13 节；能填的词，运行脚本不带参数就能看到。
> 脚本都在 `/Users/soul/work/MakeCodePlanWord/scripts/`，下面写成 `…/scripts/`。在 claude.ai 里通过连上的文件夹运行时，命令里的 `/Users/soul/work/MakeCodePlanWord` 换成 `$HOME/mnt/MakeCodePlanWord`；参数里的计划路径照写 `/Users/soul/…`。

| 什么时候 | 做什么 |
|---|---|
| 要写计划文件（只讨论方案不算） | ① 先看这个模块有没有没关闭的任务：有就不规划，告诉用户“等 Mxx-Tnnn 关闭后再做”（它在“结论中”、是在给它建修复后续时除外；确实要同时建加 `--强制`）。② `python3 …/scripts/task.py new 项目=… 版本=… 模块=… 类型=… 简称=… 来源="…"`（简称 4～10 字；要等别的任务写 `等=T019,T025:做完`）。③ 计划的文件名和一级标题都以任务号开头，里面写一节「改进度」 |
| 计划写完 | `python3 …/scripts/task.py plan <任务号> 执行计划=<全路径> [检测计划=<全路径>]`，在工作树做的再 `task.py ws <任务号> 端=… 目录=… 分支=…`，然后 `task.py set <任务号> 等待审核`。回复最后一行固定写：`<任务号> <简称> 已出，请审核` |
| 用户说通过 | `task.py set <任务号> 待执行`，回复 `请交给 <执行方> 执行：<全路径>`。用户提意见：不改状态，改完再说一次“已出，请审核” |
| 收到“某任务做完了 / 检测完了” | 先 `task.py set <任务号> <状态>`，再读计划里的报告 |
| 自己卡住、要用户决定 | 先 `task.py set <任务号> 卡住 "要你决定：……"` 再问；用户答复后 `task.py set <任务号> 继续` |
| 模块的后端 / 前端 / 自审 / 检验有变化 | `python3 …/scripts/set-status.py <项目> <版本> <模块号> 栏=值`（例：`… 喵喵漫剧网页端 v1.1.0 M08 后端=完成`）。开始修检验出的问题改 `检验=修复中`，修完、复检计划写好改 `检验=待复测`。不手改模块清单表 |

在 Claude Code 里，开工改“执行中”和答复后的“继续”由钩子自动改；“卡住”和做完改“待检测”仍要自己运行。
