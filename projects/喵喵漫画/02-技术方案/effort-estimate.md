## 1. 评估前提与假设

| 项 | 假设 |
|----|------|
| 团队配置 | 1 名 Flutter、1 名 Java、0.5 名 QA/验收支持；无专职设计师持续投入 |
| 每日有效工时 | 1 人天 = 6 小时有效开发/测试时间 |
| 估算单位 | 人天，最小颗粒 0.5 人天 |
| 估算方法 | PERT 三点估计：`E=(O+4M+P)/6`，`σ=(P-O)/6` |
| 起始日期 | 默认 2026-06-11 开始执行 |
| 工作日规则 | 周一至周五为工作日，暂不计节假日 |
| 并行度 | Flutter 与 Java 可并行；联调、QA、构建在功能闭环后逐步进入 |
| 范围边界 | 首页与资产库完整实现；其它功能只做占位页/占位弹窗 |
| 缓冲策略 | 采用标准缓冲 +20%；不采用 +40%，因为本期不接真实 AI SDK、支付和复杂生成链路 |

未提供真实团队人数、目标上线日期和示例素材交付时间，因此本评估先作为 v1.0 基线，后续可按实际人力追加 v1.1 增量评估。

### 5.2 关键路径

当前关键路径为：

```text
T-F001 -> T-F002/T-F003 -> T-F004 -> T-F005
       -> T-F006 -> T-F007 -> T-F008 -> T-F009 -> T-F010
       -> 联调测试 -> 构建打包 -> 上架发布
```

后端关键段为：

```text
T-B001 -> T-B004 -> T-B005 -> T-B006 -> T-B007 -> T-B008
```

后端期望工时短于前端，若 Java 资源稳定投入，通常不会成为总项目关键路径；若资产接口延迟，`T-F007` 会被阻塞。

## 7. 风险缓冲

### 7.1 缓冲策略

| 缓冲类型 | 本项目采用 | 原因 |
|----------|------------|------|
| 标准缓冲 +20% | 是 | 复制工程迁移、旧文案清理、Figma 无 Token、双端联调均有中等不确定性 |
| 强不确定性缓冲 +40% | 否 | 本期不接真实 AI 生成、支付、会员扣点、复杂 SDK 和商用模型链路 |

### 7.2 缓冲后的工作量

| 范围 | 基线期望工时 | +20% 缓冲后 |
|------|--------------|-------------|
| 编码 | 36.58 人天 | 43.90 人天 |
| 编码 + 联调 + 构建 + 上架 | 45.58 人天 | 54.70 人天 |

### 7.3 主要风险点

| 风险 | 可能影响 | 缓冲建议 |
|------|----------|----------|
| `appCode` 编码前改名 | 常量、配置、代码化初始化数据、测试重跑 | +0.5~1 人天 |
| 前端旧工程残留多 | UI、路由、文案清理延期 | +2~4 人天 |
| Figma Token 缺失 | UI 细节来回调整 | +1~2 人天 |
| 后端 schema/初始化数据本地环境不一致 | 联调阻塞 | +1~2 人天 |
| 商店审核资料缺失 | GA 延期 | +3~7 个自然日 |

## 8. 资源/人力变化敏感性

| 变化 | 对工时的影响 | 对日历的影响 |
|------|--------------|--------------|
| 增加 1 名 Flutter | 前端总人天基本不变，协作成本略增 | 前端关键路径可从约 24 工作日降到 14~16 工作日，GA 预计提前 6~8 工作日 |
| Flutter 只有 0.5 人投入 | 前端人天不变 | 关键路径拉长到 45~50 工作日，GA 可能推迟 3~4 周 |
| Java 只有 0.5 人投入 | 后端人天不变 | 资产接口可能从第 2 周延到第 4 周，阻塞 T-F007，整体推迟 4~8 工作日 |
| 增加 1 名 QA | QA 人天基本不变 | 联调回归从 4~5 工作日降到 2~3 工作日 |
| 没有 QA 支持 | QA 工作由开发承担 | T-F010 和联调阶段增加 3~5 人天，缺陷外溢风险上升 |
