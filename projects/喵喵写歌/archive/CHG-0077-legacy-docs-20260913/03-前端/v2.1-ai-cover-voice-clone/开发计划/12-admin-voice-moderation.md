## 1. 功能定位与边界

在 catsinger 管理域提供官方音色全生命周期、本人音色脱敏查询和统一审核操作。官方/本人音色共用后端领域，但页面权限和可编辑范围不同。

## 2. 页面落点

建议新增 `lib/pages/app/catsinger/song_voice_profiles_page.dart`，使用“官方音色 / 本人音色”Tab；详情可使用现有抽屉或对话框模式。审核继续扩展现有 AI Operations/资源视图，不单独建设另一套审核中心。

## 3. 官方音色

列表字段：名称、头像、资料状态、模型版本、provider/model、试听、发布状态、排序、更新时间。

操作：创建、编辑资料版本、上传头像/素材、发起训练、查看任务、试听、发布、下架、恢复渠道绑定。

发布门禁：资料文字/头像审核通过、模型和配置已平台持久化、试听可播放且审核通过、至少一个有效渠道绑定。编辑已发布音色产生新草稿，旧发布版本继续服务现有任务。

## 4. 本人音色

- 只读/有限运维视图，按用户、状态、厂家和时间筛选。
- 默认脱敏用户信息，不展示原始私有素材永久 URL。
- 可查看资料版本、训练任务、模型版本、渠道绑定和不可用原因。
- 仅具备运维权限时执行允许的重试/恢复，不能代替用户授权或强制成功。

## 5. 安全审核

覆盖资料文字、头像、训练音频、源歌曲、厂家试听和翻唱成品。列表显示机器结果、人工结果、原因、处理人、时间和 revision。

- REVIEW 可人工复核；必须填写原因并二次确认。
- ERROR 可按后端允许重试机器审核。
- REJECT 不能由普通运营直接改成 PASS。
- 409/revision 冲突保留表单并要求刷新。
- 所有预览使用短期受控 URL，切换记录后释放旧播放器。

## 6. Repository 与模型

新增 Admin voice profile、version、model binding、training task、moderation view models。Repository 负责分页、筛选、操作 busy、AppCode epoch 和错误；页面不直接调用 API。

- 审核 PASS/REVIEW/REJECT/ERROR、重试、人工原因、并发冲突。
- 快速切 App/筛选/详情时响应不串数据。

## 9. 验收标准

- 名称、头像由平台维护，试听来自厂家结果经平台转存。
- 普通运营不能查看无权限原始私有素材或绕过审核。
- 官方音色发布条件全部可见，后端拒绝可读且表单可恢复。
- 不提供取消训练、修改厂家状态或强制成功按钮。
