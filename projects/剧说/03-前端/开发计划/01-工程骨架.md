## 1. 功能定位与边界

工程骨架模块负责建立剧说 Flutter 工程的基础设施，让后续页面和业务模块能按统一规则接入。

本模块只做基础设施：

- App 启动入口。
- 全局初始化。
- 主题与系统样式。
- 路由框架。
- 网络、存储、事件服务抽象。
- 全局 Store。
- 通用 UI 组件。
- Mock / adapter 基础开关。
- 最小可运行主框架占位页。
- 工程内 Cursor 规则落地：在 Flutter 工程内写入 `.cursor/rules/`，后续编码以工程内规则为准。

本模块不做：

- 登录业务页面完整实现。
- 创作页、作品页、我的页的真实 UI。
- 后端真实接口联调。
- 支付、上传、生成任务真实能力。

## 6. 业务内容与数据流

### 6.1 启动数据流

```text
main()
  -> WidgetsFlutterBinding.ensureInitialized()
  -> SystemChrome.setSystemUIOverlayStyle()
  -> Global.init()
  -> StorageService.init()
  -> register services
  -> register stores
  -> runApp()
  -> MaterialApp.router()
```

### 6.2 Mock / adapter 数据流

```text
Controller
  -> Api method
  -> HttpService
  -> MockService enabled ? mock response : real adapter
  -> Model
  -> Store / Controller
  -> View
```

真实接口待确定期间，`MockService` 默认可用，API 层不得写死最终 URL。

### 6.3 全局状态流

- `UserStore` 保存 mock token、用户信息、积分和会员状态。
- `ConfigStore` 保存协议勾选、版本信息和 mock 开关。
- `CreationStore` 预留创作草稿字段，后续创作模块接入。
