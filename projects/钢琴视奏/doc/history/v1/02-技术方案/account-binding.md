# CHG-20260926-ACCOUNT 账号绑定实现与验收

状态：done（本地实现及专项验收，未生产发布）。用户已批准完整实施方案，以下为研发增量契约，外部产品设计基线继续保持唯一真源。

## 已批准需求及评审

用户确认每个用户先建独立本地账号。注册新用户名、首次 Google、首次游客绑定当前本地账号，退出新建空白账号。登录已有身份切换到目标账号，原数据不合并，退出恢复原账号。游客升级到未占用身份保留服务端 ID 与权益，旧游客凭证及会话撤销，退出新建账号。新模型仅一种绑定，历史邮箱密码及多身份兼容。以上需求和异常处理已经用户批准，无待决产品问题。

## 契约与实现

- 仅 Solfeggio 使用 POST /api/v1/account/auth/{register,password-login,google-login,guest-login,upgrade,logout}；公开认证仍验证密码、Google subject 或游客凭证，upgrade 要求当前游客会话。响应组合 session: LoginResponse 与 transition: BOUND_CURRENT / EXISTING_ACCOUNT / UPGRADED_CURRENT。
- 客户端提交 localProfileId 与 Idempotency-Key，仅用于关联和幂等，不作为认证凭证。操作记录保证响应丢失重放保持原 transition。事务串行化操作、目标身份和升级用户，数据库唯一约束兜底。
- 用户名注册 3–32 ASCII 字母数字下划线，不区分大小写；登录保留历史邮箱。Google 只按验证 subject 识别，不按邮箱自动关联。core 负责身份/用户/会话写入，app/solfeggio/auth 维护绑定和操作回执。
- 新增 V3.3 专属迁移，保留所有已有迁移；不修改其他 App 的登录行为。游客升级同一 userId，不触碰订单、会员和资产归属。
- LocalAccountManager 持久化当前账号、云映射、登录前账号和退出动作；迁移登记旧命名空间且不删除原数据。各账号隔离练习、等级、上传队列、缓存、收藏、头像昵称和偏好，隐私/权限/服务器为设备级。
- 绑定当前才上传原数据；已有账号同步目标数据，暂停原队列；重启及刷新保留退出模式。失败/取消不切换，迟到响应按会话版本丢弃，上传失败保留绑定与队列。
- 游客恢复及待撤销任务用平台安全存储。退出先可靠保存撤销任务并立即本地切换，在线发送、离线重试；升级成功撤销旧游客凭证并清除恢复入口。
- 具体持久化：GetStorage 账号注册表一次写入当前账号、映射、退出模式、会话和操作键，等待写队列；旧分区只登记不删除。升级成功回执丢失后，原有效 JWT 可精确重放；后来使用新身份验证到相同 userId，可确认本地待恢复升级并清除旧游客恢复入口。
- V3.3 本功能新增绑定、操作回执和认证事务互斥三表；互斥行串行化新模型认证。历史身份表复用；Google 邮箱仅提供 masked 展示。同一文件内其他任务的未发布增量保留。仅测试库执行，未修改正式库或执行生产 Flyway。
