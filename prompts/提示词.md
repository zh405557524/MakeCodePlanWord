# 提示词

复制对应的提示词，把 `{}` 换成实际内容。工作台路径是 `/Users/soul/work/MakeCodePlanWord`，换电脑时整体替换。
`{docRoot}` 是项目文档目录，默认 `/Users/soul/work/MakeCodePlanWord/projects/{项目名}/doc`；提示词里的 `doc/xxx` 都指它，不是代码仓库里的 doc 文件夹。

典型分工：**规划类（P1–P4、P6、P8–P11）交给 Claude**；**执行类（P5、P7）交给 ChatGPT / Codex**，在代码仓库里打开会话。

## P4 写开发计划（给执行 AI 用）

```
项目：{项目名}，版本：{vX.Y.Z}，文档目录：{docRoot}
涉及仓库：{App 仓库路径}、{后端仓库路径}
按 /Users/soul/work/MakeCodePlanWord/workflow/04-开发计划.md 写 versions/{vX.Y.Z}/plan.md，同时在 test.md 写好新增用例。

这份计划会交给 {ChatGPT / Codex} 执行，它理解力有限，所以：
- 先读每个涉及仓库的 AGENTS.md 和规范索引里相关的规范，把关键条款写进"本次已读规范"。
- 先读相关的现有代码，写出要复用的组件和参考实现的具体路径。
- 每个任务写全路径、具体做法、要新建的名字、验证命令、对应用例；不要出现"按需""酌情""参考现有实现"这类词。
- 接口字段写类型、可空、单位；金额写币种和精度，时间写时区。
- 写完按文档第 8 节的审核清单自查，再交给我审核。
```

## P5 执行计划（在代码仓库里交给 ChatGPT / Codex）

```
执行 {docRoot}/versions/{vX.Y.Z}/plan.md 中的 {T-01 到 T-03 / 全部未完成任务}。

开始前：
1. 读本仓库根目录的 AGENTS.md，再按它的"规范索引"读和这些任务相关的规范文件。
2. 读 plan.md 全文。确认状态是"已审核"或"执行中"，不是的话停止并告诉我。

执行时：
- 按任务顺序一个一个做。开始前把任务状态改为"进行中"，完成后改为"完成"，并在"结果"里写：做了什么、提交号、和计划不一致的地方。
- 只改任务里列出的文件。需要改其他文件、计划写的文件不存在、需求有矛盾、验证失败原因不在本任务内：立即停下来报告，不要自己发挥。
- 每个任务完成后跑任务里的验证命令和 AGENTS.md 规定的验证命令，全部通过才算完成。
- 不要修改 {docRoot}/product/ 和 {docRoot}/tech/（文档目录在工作台，不在本仓库）。

全部做完后给我：完成的任务、每个任务的验证结果、偏离计划的地方、遗留问题。
```
