## 入口、职责和表单

管理员切到 Catsinger、具备 `song_config` 权限后，在既有歌曲配置页分别编辑“新用户注册赠额”和“新人礼弹窗”。两个配置块独立保存/独立版本；赠额是**建号时发积分**，新人礼“领取”仅转签到/任务中心，**不是第二次赠额**。当前工程有 `UserService` 建号发默认 30 的现有链路与通用配置页，但无这两个专用编辑区；不得新增平行积分业务或借页面触发补发历史积分。

| 配置块 | 字段与界面行为 | 保存校验 |
|--------|----------------|----------|
| 注册赠额 | 当前有效值、下一新账号可用值、固定初始化/坏值兜底 30 的说明、配置版本；管理员输入正整数并保存 | 只允许 Catsinger，非正数/越界按后端规则拒绝；历史账号不回填、游客绑定不重发 |
| 新人礼 | 启用状态、审核过的弹窗 `imageResourceId`/可展示文案 `textResourceId?`、适用新用户人群与会员条件、`ONCE/DAILY/PER_OPEN` 频次、固定上线资格起点、签到/任务等目标白名单、配置版本 | 必填项、发布资源审核态、目标、资格起点只可按后端允许方式保存；已领资格不能后台重置 |

页面区分“当前配置值有效”“当前配置缺失/非法而运行时回退 30”“配置服务故障”三种状态；只有前两种可按 B008 解释数值，服务故障不可展示为成功兜底。任务中心的签到/任务奖励由原规则接口管理，本页不把设计图示例 `100/120/+3/+10` 写死。

### 真实实现阶段 / T-W004-R

1. 赠额配置通过 B008-R 的专用 API 读取并保存；对配置缺失/非法显示 30 的运行时兜底提示，但本次保存必须写合法正整数。管理员改为 100/200 后只对**以后建的符合条件账号**生效，不触发历史余额重算、批量发放或账户迁移。
2. 新人礼通过 B009-R 发布：图、可展示文字与目标均按既有安全审核/白名单流程；待审/驳回不可发布。频次按新用户**点击领取前**生效；“稍后”撤销当前展示，不结束资格。`DAILY` 的业务日按服务端 `Asia/Shanghai`，Web 只说明口径不自行计算资格。
3. 资格起点由后台固定发布，后续不能通过改时间让历史账号突然符合；具体字段和修改限制以 Java 同版契约为准。后台“关闭”只停未来展示，不改历史 `claimed_at`，重启不使已领用户重新可领。
4. 两个 `PUT` 分别带所见版本；409 保留草稿、提示线上已更新，不静默覆盖。Catsinger 专用和通用配置入口都经 B008/B009 同一校验；跨 App/无权限/无审核资源拒绝并可审计。
5. 发布后以新建测试账号核对实际积分流水和新人礼资格；同账号游客绑定、老账号、已领账号、另一个 App 不受设置变化影响。管理页看到“保存成功”不等于真实发放成功。
