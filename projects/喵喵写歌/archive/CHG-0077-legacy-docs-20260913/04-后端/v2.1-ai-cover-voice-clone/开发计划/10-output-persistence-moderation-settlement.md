## 1. 功能定位与边界

把厂家翻唱结果安全下载并持久化到平台，识别实际音频格式，完成内容审核、服务端可播放检查、作品创建和积分结算。厂家“成功”或临时 URL 可访问不等于业务成功。

## 2. 成功流水线

```text
Provider SUCCEEDED
  -> 下载候选资源
  -> 平台持久化
  -> 文件头/MIME/后缀/大小/时长探测
  -> 服务端解码/可读取检查
  -> 输出内容审核
  -> 创建 VOICE_COVER 作品
  -> 确认积分扣减
  -> 任务 SUCCEEDED
```

任一步最终失败都不创建可见成功作品，并进入积分释放或现有补偿。

## 3. 下载与安全

复用 `HttpResourceDownloader`、`ResourceRecordService` 和存储策略。限制协议、重定向、域名/IP、连接/读取/总超时、最大体积和内容类型，防止 SSRF 与无界下载。厂家临时 URL 不写最终作品 URL。

## 4. 实际格式

以后端下载内容的文件头和媒体探测为准，记录 audioMimeType、fileExtension、fileSize、durationMs。不得默认 MP3，不得只信请求输出格式或 URL 后缀。

若厂家未来返回分轨，当前版本仍只选择技术方案确认的最终混音资源；能力变化另建 CHG。

## 5. 输出审核与作品

- 探测成功后创建输出审核记录并等待 PASS。
- REVIEW 进入人工复核；REJECT/ERROR 最终不发布。
- 审核 PASS 后通过现有作品 Service 幂等创建 `songType=VOICE_COVER`，保存音色资料/模型版本和来源快照。
- 服务端再次验证受控资源可读、可解码和时长合理。

## 6. 积分和幂等

资源持久化、审核关联、作品创建和结算分别使用任务业务唯一键。重复调度返回已有资源/作品/流水。只有可播放作品建立后确认扣减；失败统一释放冻结，结算失败进入现有补偿而不重复创建作品。

## 7. deadline

持久化、探测、审核和作品创建均计入接单后的 10 分钟。步骤执行前后检查 deadline；超过时按工作流规则失败，晚到结果不能覆盖终态或重复结算，资源按孤儿清理策略处理。

## 8. 实现步骤

1. 接入 Provider 成功资源候选与安全下载。
2. 幂等写平台资源并探测真实属性。
3. 执行服务端可播放校验和输出审核。
4. 幂等创建 VOICE_COVER 作品及快照。
5. 确认积分、完成任务并处理各阶段补偿。

## 9. 测试要求

- MP3/WAV/M4A/FLAC/OGG/AAC 实际识别和伪装后缀。
- 临时 URL 失效、重定向、私网地址、超大、超时。
- 下载成功但解码失败、时长异常、审核拒绝/异常。
- 重复步骤只产生一个资源、作品和扣费。
- deadline 后晚到厂家结果不能改回成功。
- 结算失败可补偿，旧业务流水不受影响。

## 10. 验收标准

- 最终作品只引用平台资源，返回真实格式和受控访问。
- 真实播放门禁、输出审核和积分结算全部闭环。
- 厂家成功但平台失败时任务如实失败且积分最终释放。

## 11. 编码注意事项

外部下载和审核不放在长事务中；每一步写可恢复事实。不要用 HTTP 200 代替音频可播放，也不要为声音克隆新建资源或积分体系。
