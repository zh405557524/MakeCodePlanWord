## 1. 背景和需求

现状（`f30ad04d`、`dff65887`，技术方案 T-02 A、D-22）：**场景主体下面只要挂着没删的子场景，就认为主图是俯视总图**——
- 出主图时：生图变量 `sceneView = 俯视总图`，描述后面附上“【各子场景】名称：外观”；
- 拆片段、片段重写时：可用素材里去掉这个主场景，只用子场景。

用户 2026-11-25 的决定：**场景就是“主图 + 子图”，主图可以是俯视图，也可以是别的图。只有剧本建出来的场景，主图才给俯视图**（剧本知道整个场所的结构；后台、资产库手动建的场景可能就一句话，出不了俯视图）。

- R1 **“主场景是俯视总图”只用一个判断**：场景主体 + 下面挂着没删的子场景 + **主体是剧本分析建的**（库里 `source_type = 'ANALYSIS'`；本次分析新建、还没入库的 `existing = false` 的条目也算）。下面第 2 节的每个判断点都用这同一个条件，不各写一套。
- R2 满足 R1 的：和现在一样（出俯视总图、附子场景描述、片段里不用主场景）。
- R3 不满足 R1 的：主场景就是普通场景图——
  - 出主图不带 `sceneView`、描述不附子场景；
  - 拆片段、片段重写时主场景和子场景都在可用素材里。
  - 包括：手动建的（`MANUAL` / `UPLOAD`）、从作品存进资产库的（`PROJECT_GENERATION`）、导入的（`PERSONAL_IMPORT` / `SYSTEM_IMPORT`）、官方素材（`OFFICIAL`）和官方运营账号里的生成载体。
- R4 不做数据迁移。已经按俯视总图出过的主图保持原样；按新规则不该是俯视图的，用户重新生成一次就是普通场景图。
