# 09-模块与接口

> 什么时候读：新增或修改接口、跨模块调用、写计划、做大功能。只在模块内部改实现时不用读。
> 本规则解释仓库 `AGENTS.md` 里的两条红线，并规定新接口该写成什么样。目标：维护者不读实现，也能看懂每个模块对外提供什么。

## 一、模块是什么

- 一个模块是一个职责独立的业务包。
- 模块的**公开接口**只有两种：它的 Controller 暴露的 HTTP 接口；它提供给其他模块调用的 Service 公开方法。
- 模块的**内部**包括：Repository、Entity、表、内部辅助类，以及对接外部系统的实现。
- 别的模块只能用公开接口。需要对方的数据就调对方的 Service，不注入对方的 Repository，不直接查对方的表。

## 二、什么算“动了接口”

| 算，属于“先问” | 不算，可以自主 |
|---|---|
| 新增、删除、改名一个 HTTP 路径或方法 | 改方法内部的实现 |
| 请求或返回里增、删、改字段，或改字段的含义 | 新增内部类、私有方法 |
| 新增或改变状态值、错误码 | 改日志、注释 |
| 给其他模块用的 Service 方法改签名或含义，或新增这类方法 | 调整只在本模块内使用的方法 |
| 新增、修改表或字段 | 改查询写法但结果不变 |
| 把“用户确认后才进行”改成“自动进行”，或反过来 | 改内部执行顺序但对外表现不变 |

拿不准算不算时，按“算”处理。

## 三、接口六条

约束新增的接口。现有接口不因为这六条而改动。

1. **一句话说得清。** 每个接口方法都能用一句人话说明“给什么、得什么”。说不清就不加。
2. **固定形状。** 耗时的能力统一两步：提交，查询。同一能力不同时提供同步和异步两套。
3. **只传业务参数。** 给业务模块用的接口上不出现厂商、模型、令牌、追踪号这类内部信息。
4. **参数拍平。** 入参是一层看得懂的字段；出参只有状态、结果、失败原因。
5. **先交接口卡片。** 新增接口方法先把接口卡片交给用户，批准后再实现。卡片格式见工作台 `workflow/03-技术规划.md`。
6. **不超过 7 个方法。** 一个接口的方法超过 7 个，说明它管得太多，先提出拆分方案。

## 四、现有代码

- 现有代码里已有的跨模块直接访问、过大的接口，不借本规则顺手清理；清理要用户明说。
- 新写的代码不再增加这类情况。任务必须沿用旧写法才能完成时，在交付里说明。
