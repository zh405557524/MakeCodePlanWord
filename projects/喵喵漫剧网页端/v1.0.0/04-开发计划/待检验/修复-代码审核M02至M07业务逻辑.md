### T-03 分镜页：定时刷新不能盖掉刚保存的描述（C4）

- 状态：完成（待验证）
- 问题：`lib/pages/storyboard/controller.dart`。有片段在生成时，`_scheduleShotsPoll` 每 3 秒调一次 `_loadShots` 刷新片段列表。时间线：① 刷新请求发出；② 用户的描述保存成功，`_saveDescription` 用返回的新片段替换了列表里的片段、并把草稿从 `_drafts` 里删掉；③ 刷新请求返回（内容是保存之前的旧数据），`shots.assignAll(rows)` 把片段换回旧的，`_refreshInputFromShot()` 发现没有草稿，就把输入框改回旧文字。之后用户再打字，保存用的是旧 `revision`，后端返回 `-560001`，代码按“内容已在别处更新”丢弃草稿——用户这段修改丢了。
- 可改文件：`lib/pages/storyboard/controller.dart`；新增 `test/pages/storyboard_poll_guard_test.dart`
- 具体做法：
  1. 控制器里加一个计数 `int _shotsEpoch = 0;`，含义：本页自己改过片段列表的次数。
  2. 下面三处，在改动 `shots` 之后各加一句 `_shotsEpoch++;`：
     - `_replaceShot`（保存描述成功、应用视频、确认描述后都会走到）；
     - `_saveSettings` 里 `shots.assignAll(rows);` 之后；
     - `_loadShots` 自己成功 `shots.assignAll(rows);` 之后（这样连续两次刷新也不会乱序覆盖）。
  3. `_loadShots` 加一个参数：`Future<void> _loadShots(String id, {bool showLoading = false, bool fromPoll = false})`。函数开头记下 `final startedEpoch = _shotsEpoch;`。在 `final rows = await DramaShotsAPI.list(id);` 和原有的 `if (_closed || id != episodeId.value) return;` 之后、`shots.assignAll(rows);` 之前加：
     ```dart
     if (fromPoll && discardPolledShots(startedEpoch: startedEpoch, currentEpoch: _shotsEpoch, pendingSaves: _pendingSaves)) {
       _scheduleShotsPoll();
       return;
     }
     ```
  4. 加一个纯函数（放在 `StoryboardController` 里）：
     ```dart
     /// 定时刷新的结果要不要丢掉：刷新期间本页改过片段列表，或还有保存没做完，就丢掉，下一轮再刷新。
     @visibleForTesting
     static bool discardPolledShots({required int startedEpoch, required int currentEpoch, required int pendingSaves}) =>
         startedEpoch != currentEpoch || pendingSaves > 0;
     ```
  5. **只有定时刷新那一处**传 `fromPoll: true`：`_scheduleShotsPoll` 的定时器回调里的 `await _loadShots(id);` 改成 `await _loadShots(id, fromPoll: true);`。其他所有调用 `_loadShots` 的地方（进入剧集、保存冲突后重读、应用视频冲突后重读、生成提交后重读、`generation.dart` 里的调用）都不加，保持“一定采用返回结果”。
  6. `generation.dart` 不用改（它调用 `_loadShots` 的地方都不是定时刷新）。
- 测试（`test/pages/storyboard_poll_guard_test.dart`）：只测纯函数 `StoryboardController.discardPolledShots`：
  - 开始和结束计数相同、没有保存在做 → `false`；
  - 计数变了 → `true`；
  - 计数没变但 `pendingSaves = 1` → `true`。
- 不要做：不改自动保存的延迟和排队方式；不改 `-560001` 冲突时“放弃草稿、换成最新内容”的处理；不改轮询间隔。
- 验证：`flutter test test/pages/storyboard_poll_guard_test.dart test/models/drama_shot_test.dart`；`flutter analyze`。手动（有条件时做，没有作品数据就写“未做：没有处于片段阶段的作品”，不为此去生成）：用 `--dart-define=MOCK_NEW_API=true` 打开分镜页假数据里有片段在生成的那一集，连续修改描述 20 秒，输入框文字不被改回、不出现“内容已在别处更新”。
- 完成标准：测试通过；`fromPoll: true` 只出现在定时刷新一处（`grep -n "fromPoll: true" lib/pages/storyboard` 只有 1 行）。
