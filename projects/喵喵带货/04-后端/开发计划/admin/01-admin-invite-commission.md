## 1. 功能定位与边界

将现有 InvitePage 的“用户代理配置”页签在新模式下切换为“邀请与佣金查询”，展示关系、有效人数、首单转化、购买时比例快照、正向奖励与退款冲正。新模式只读，不手动调等级/二级资格，不新建重复菜单。

数据库改动：无，Admin 只消费 Java API。

## 4. 视觉参考与设计稿分析

后台无 Figma，复用现有表格/筛选/分页/详情样式。页面从上到下：筛选区、用户邀请摘要列表、选中用户/订单的佣金流水详情。正向和负向金额必须有符号和文字，不只靠颜色区分。

## 5. API 与 Model 合同

| API | 请求 | 响应 |
|-----|------|------|
| `GET /api/admin/invite/users` | 当前 App 筛选/分页 | 脱敏用户、关系、有效人数、首单转化、当前比例 |
| `GET /api/admin/invite/commissions` | 当前 App 用户/订单/类型/时间等合同筛选与分页 | 订单号、比例/人数快照、正向奖励/退款冲正、原流水关联 |

所有金额为分，不由 Admin 重算佣金。错误包含 403/App 范围、参数错误、网络失败；不暴露 SQL 或工猫报文。

## 6. 业务内容与数据流

1. 当前 App capability 确认后才加载查询。
2. 筛选使用服务端分页，切换筛选/App 清空选中详情并忽略旧响应。
3. 用户摘要显示当前等级，订单流水显示购买时快照，不混用。
4. 冲正显示负数、原订单/原奖励关联和安全原因；提现扣款/返还在提现详情，不放此表。
5. LEGACY 仍走原代理配置与权限。
