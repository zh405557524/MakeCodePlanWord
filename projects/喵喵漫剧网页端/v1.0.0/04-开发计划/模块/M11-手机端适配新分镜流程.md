- 具体做法：
  1. 按清单加枚举值和可空字段：`AnalysisProblem` 模型含 `reasonCode`、`suggestion`、`category`、`message`、`shotNumber`、`excerpt`；剧集 `shotGeneration` 含 `state`（`NONE`/`RUNNING`/`READY`/`FAILED`，没有这个字段或取值不认识都按 `NONE`）、`jobId`、`problemShotCount`、`failureReason`、`rawOutput`；片段 `analysisProblems` 没有时按空列表；`assetPlan` 只解析不显示。
  2. `DramaJob.fromJson` 放宽（只改这两处，其他校验不动）：

     - 失败原因用任务现有的 `errorMessage` 显示，不新增 `analysisFailure` 字段。
  3. `regenerateDescription(shotId, expectedRevision, overwriteConfirmed, key)`：`POST /api/drama/shots/{shotId}/description-tasks`，请求体 `{expectedRevision, overwriteConfirmed}`，请求头 `Idempotency-Key`；返回的任务核对 `kind = SHOT_DESCRIPTION`、`targetId = shotId`、`financialState = FREE`。
  4. `lib/routes/episode_destination.dart`：两个 `switch` 都加 `'SHOTS'`，和 `'VIDEOS'` 走同一个分支（去镜头制作页，入口状态取 `entryState['shots']`）；镜头制作页再按 `shotGeneration.state` 决定显示什么（F-03）。

- 后端 M04～M06 上测试环境后、本模块完成前，测试环境上旧版手机端进不了镜头制作（把 `SHOTS` 当不可用）。正式上线时后端和手机端新版要一起发。
- **已经装在用户手机上的旧版 App**：后端新版上线后，旧版在三处会出错——确认素材后提示失败（旧版要求返回 `VIDEOS`）、看到 `SHOT_DESCRIPTION` 任务或带原始返回的失败任务时提示数据无效、`SHOTS` 的集被带去剧本页。上线时需要用现有的强制更新（`forceUpdate`）让旧版升级，这件事放到上线阶段由用户决定，本模块不处理。
- 差异核对沿用剧本页现有流程：它靠本机记下的待核对编号显示，换手机或清数据后编号没了，这时靠镜头制作页现有的“待核对”提示进入（不新增）。
- 回滚：手机端回退到改动前的提交。
