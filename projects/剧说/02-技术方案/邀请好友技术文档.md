## 1. 技术目标

围绕邀请关系新增可追踪、可配置、可审核的收益闭环：

- 登录 / 注册链路支持邀请码承接。
- 邀请关系一次性绑定并保证幂等。
- 注册奖励积分通过既有积分账务发放，默认 `10` 积分且后台可配。
- 会员返佣通过支付成功回调结算，仅处理被邀请人的首次开通会员订单。
- 个人代理等级只影响直接邀请返佣；关系层级只影响直接 / 间接收益范围。
- 收益账本记录现金收益来源和状态。
- 提现记录支持冻结、审核、驳回、打款成功、打款失败。
- 后台 Web 支持规则配置和提现管理。
- 公开落地页支持邀请链接注册和下载地址展示。

## 6. 状态流转

| 对象 | 状态流转 |
|------|----------|
| 邀请关系 | `UNBOUND -> BOUND`，终态不可修改 |
| 注册积分 | `PENDING -> REWARDED / DISABLED / FAILED` |
| 直接会员返佣 | `PENDING -> SETTLED / SKIPPED / FAILED` |
| 间接会员返佣 | `PENDING -> SETTLED / SKIPPED / FAILED` |
| 提现 | `PENDING_REVIEW -> APPROVED -> PAID` |
| 提现驳回 | `PENDING_REVIEW -> REJECTED`，退回可提现余额 |
| 打款失败 | `APPROVED -> PAY_FAILED`，退回可提现余额 |

## 7. 幂等与事务

- 邀请关系以 `inviteeUserId` 保证一个用户只绑定一次。
- 注册积分默认 `10` 积分，以 `inviteeUserId + REGISTER_POINTS` 保证不重复发放。
- 直接会员返佣以 `sourceUserId + DIRECT_MEMBER_COMMISSION` 保证同一被邀请人只在第一次开通会员时结算一次。
- 间接会员返佣以 `sourceUserId + INDIRECT_MEMBER_COMMISSION` 保证同一间接被邀请人只在第一次开通会员时结算一次。
- 邀请绑定和注册送积分需要在同一事务中完成。
- 直接返佣比例按直接邀请人结算时的个人代理等级快照计算：1 级 `10%`，2 级 `20%`，3 级 `30%`。
- 个人代理 2 级在直邀人数达到 `10` 后对后续被邀请人生效；个人代理 3 级在直邀人数达到 `30` 后对后续被邀请人生效，已结算订单不追溯。
- 间接返佣只处理一层，即被邀请人的直接邀请人的直接邀请人；固定 `10%`，不读取个人代理等级。
- A->B->C->D 中，D 首次开通会员时 C 获得直接返佣；B 若开启间接收益资格则获得 `10%` 间接返佣；A 不获得收益。
- 续费会员、再次开通会员、充值积分不触发返佣。
- 提现申请需要冻结可提现收益，驳回或打款失败后释放冻结。
- 注册积分必须通过 `PointsService` 追加流水，不能直接修改积分余额。
- 打款成功只推进提现和账本状态，不删除历史记录。

## 8. 安全与合规

- 邀请链接中的邀请码不是鉴权凭证，仅用于绑定关系。
- 提现账号属于敏感信息，后台列表默认脱敏展示。
- 后台提现审核操作需要记录操作者、时间和备注。
- 后台开启 / 关闭用户间接收益资格需要记录操作者、时间和备注。
- 后台审核接口必须检查后台鉴权。
- 公开落地页只能展示必要信息，不返回邀请人敏感资料。
- 提现提交按钮和后台审核按钮都需要防重复提交。
