## 3. 现状摘要

后端（`src/main/java/com/lxwx/narrateservice/app/catdrama/`）：

1. 素材分析受理：`project/service/DramaProjectAnalysisService#analyze` → `prepareAnalysis`（作品锁内）：
   - 作品 `S11` 拒绝；版本不等 `-560001`；有进行中的 `PROJECT_ANALYSIS` → `-560005`；
   - **最近一次分析成功且各集版本没变 → `-560005`“请继续查看原分析结果”**；
   - 剧本还没确认、没保存制作设置 → `-560002`；
   - 只选 `script_revision ≠ analyzed_script_revision` 的集，**都分析过 → `-560002`“所选剧集已有当前分析结果，无需重复分析”**（`analyzed_script_revision` 在本集片段分析应用时写，所以进入片段阶段的集一定被挡）；
   - 快照：全部有效集的标题和剧本（AI 读全剧）、`episodeIds`（要补关联的集）、`assetRegistrySeed`（`DramaAssetProjectService#analysisSeed`：作品里没删除的素材，作为“已有身份”，`existing = true`）、模板、模型、制作设置；**失败过、剧本相同的历史任务有注册表时复用（`frozenRegistry`）**；
   - 然后 `jobs.preApproveCreate` → 再次 `prepareAnalysis` 比对 → `jobs.submit(PROJECT_ANALYSIS, "PROJECT", projectId, 作品版本, …)`；作品不在 `EPISODE_PRODUCTION` 时才调 `process.analysisAccepted`。
2. 素材分析执行：`analysis/service/DramaAnalysisService#projectStep` → `VALIDATE_TEXT` 建注册表 → `COMMIT_DELIVERY` 的 `commitAssets`（第 573 行起）：对 `episodeIds` 里每一集，`DramaEpisodeAssetMatcher.match(registry, 集序号, 素材清单)` 得到本集要用的标记，`projects.withAnalysisTarget` 里**第一次进来时 `registerAnalysisAssets(全部注册表)`**（已有的跳过，新的建 `DRAFT` 素材、没有图片），再 `firstAnalysisBindings(本集要用的标记)`（只补关联；**已归档的不复活**）。最后任务 `SUCCEEDED`，结果 `JobResult("ANALYSIS", 任务ID)`。
3. **剧集阶段**：`project/service/DramaEpisodeStageService#onJobStateChanged` 对 `PROJECT_ANALYSIS` 成功调 `assetsBound`：对作品**全部有效集**做 `ASSETS_BOUND` 迁移（规则只允许从 `ANALYSIS` 出发，但 `transitionSystem` 遇到非法起点只记日志、**照样改成 `MATERIALS`**）。所以直接复用素材分析，会把已在片段 / 视频阶段的集改回素材阶段——这是本模块必须改的原因之一。

- 具体做法：
  1. **请求体** `DramaProjectRequest.EpisodeReanalysis(@NotNull @Min(1) Long expectedRevision)`，`@Schema(name = "DramaEpisodeReanalysisRequest")`，严格 `Reader` 只允许 `expectedRevision`（照 `AnalysisReader`）。
  2. **端点** `DramaEpisodeController`：`POST /{episodeId}/asset-analysis-tasks`，`Idempotency-Key` 头必填，返回 `ApiResponse<DramaJobResponse>`；Swagger 注解照同文件 `confirm-materials`（中文说明：重新识别本集素材，只补不删，免费）。
  3. **受理** `DramaProjectAnalysisService#reanalyzeEpisode(userId, episodeId, key, input)`：
     - 幂等键格式、参数校验同 `analyze`（错误 `-400`“分析任务参数不完整”）。
     - 同键已有任务（`jobs.existingSubmission(userId, PROJECT_ANALYSIS, key)`）：快照 `reanalyzeEpisodeId` 和 `request.expectedRevision` 都一样 → 返回原任务；否则 `CATDRAMA_IDEMPOTENCY_CONFLICT`。
     - 找剧集（本人、有效），找不到 `NOT_FOUND`；拿到作品 ID。
     - 后面照 `analyze` 的两段式（`prepare` → `preApproveCreate` → 作品锁内再 `prepare` 比对 → `attachCreateApproval` → `jobs.submit`）。**不调用 `process.analysisAccepted`**（作品流程不变）。`jobs.submit` 的 `inputRevision` 用作品版本（和素材分析一样），`episodeId` 参数传 `null`（和素材分析一样，避免被当成本集的单集任务）。

## 9. 风险与回滚

1. 要读全剧剧本，集数多时可能一两分钟；期间整个作品不能再跑别的素材分析（后端原来就只允许一个）。
2. AI 可能识别出“其实是同一个人、但名字写法不同”的新角色（和第一次素材分析一样的风险）；补进来的素材可以在卡片上删掉，删掉后再重新分析也不会回来。
3. 本集在片段 / 视频阶段时补进来没有图片的素材：要先生成或匹配图片才能“批量生成提示词”（现有规则，需求 4.19 已写明）。
4. 原素材分析成功会把全作品的集设成“素材”阶段（`transitionSystem` 容忍非法起点）——这是现有行为，本模块只让重新分析不走这条，原素材分析不改（它只在进入整理资产之前跑，那时各集都在分析阶段）。
5. 重新分析期间（一两分钟）手机端“修改剧本后重新分析”会被后端拒绝（`-560005`，同一作品只能有一个素材分析），等完成后再点即可；反过来也一样。
6. 回滚：后端撤回 §6.1 的文件改动（没有表结构改动；已补进来的素材和关联是普通数据，留着不影响）；网页端撤回 §7 列出的文件。
