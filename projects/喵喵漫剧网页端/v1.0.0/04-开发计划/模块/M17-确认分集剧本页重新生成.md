## 3. 现状摘要

网页端（`lib/pages/screenplay/`）：

1. `view.dart`：`ScreenplayViewState` 四种状态——`waiting`（`CreationWaiting`，“正在生成分集剧本”+ 进度）、`failed`（`CreationFailure`，“重新生成”= `controller.retry`、“返回修改原文”）、`result`（`_buildResult`：`FlowPageHeader(action: FlowGradientButton(label: 设置画面, busy: controller.busy.value, onTap: confirm))` + 左“剧集目录”+ 右当前集编辑框）、`loading` / `error`。
2. `controller.dart`：
   - `load(context)` → `_show(context, project)`：作品在 `GENERATE_SCREENPLAYS` → 等待页（`JobWatcher` 跟进度，结束后再 `load`）或失败页；在 `CONFIRM_SCREENPLAYS` 且有 `pendingCandidate`（`target == 'SCREENPLAYS'`）→ `_apply` 应用生成结果，再 `_fill` 显示。
   - `_apply`：先不带覆盖应用（键 `apply-candidate-$jobId`）；后端 `-560017`（剧本手改过）→ 弹 `creationApplyOverwrite`“新生成的内容将覆盖你修改过的内容，确定使用吗？”→ 确定后带覆盖再应用（键 `apply-overwrite-$jobId`）。
   - 自动保存 `_saver`（`AutoSaver`，`_save` 调 `DramaContentAPI.saveEpisodes`，成功后 `_project` 换成最新）；`_saver.flush()` 把没保存的存完，存不上返回 `false`。
   - `busy`：“设置画面”的提交中；`retry`（失败页“重新生成”）带原任务 ID 重试，写法：`_retryKey ??= IdempotencyKey.create()` → `DramaContentAPI.submitScreenplays(project.id, key, expectedRevision: project.revision, taskId: …)` → `load(context)`。
3. `DramaContentAPI.submitScreenplays(projectId, key, {expectedRevision, overwriteConfirmed = false, taskId})` 已有。
4. `FlowGradientButton(label, onTap, busy, width = 188, height = 58, fontSize = 18, outlined)`：`outlined: true` 是描边次按钮（浅色紫边紫字白底；深色青边青字），`onTap == null` 时半透明不可点。
5. `AppConfirmDialog.show(context, title: …)`：只有标题，“取消”“确定”，返回 `bool`。

后端（只读核对，不改）：

1. `DramaContentService#generate`（剧本）：版本不对 `-560001`；剧本手改过（`screenplaysManualEdited`）且没带 `overwriteConfirmed` → `-560017`；已有剧本任务在跑 → `-560005`；原创 / 小说按已确认的故事大纲生成（`SCREENPLAYS_GENERATE`），**已有剧本类作品把原剧本重新拆成分集（`SCREENPLAYS_SPLIT`）**；受理后作品回到“生成剧本中”（S5）。
2. 应用结果（`DramaScreenplayService#apply`）：`screenplaysManualEdited` 为真且没带覆盖 → `-560017`。**这个标记在提交生成时不会清掉**，所以剧本手改过的作品重新生成完成后，应用时后端还会要求覆盖确认——本模块在同一页面内已经问过一次，不再问第二次（F-02 第 4 步）。

#### F-02 按钮、确认、提交、应用

- 状态：进行中
- 关联需求：AC-37-1～AC-37-5
- 文件：`lib/pages/screenplay/view.dart`、`lib/pages/screenplay/controller.dart`
- 做法：
  1. **控制器状态**：`final regenerating = false.obs;`；`String? _regenerateKey;`（提交的幂等键：网络失败时下次复用，成功或后端明确拒绝后清掉）；`String? _overwriteConfirmedJobId;`（这次在页面上确认过覆盖、提交成功的任务 ID）。
  2. **`regenerate(context)`**（按钮点击）：
     - `busy.value || regenerating.value` → 直接返回；`_project == null` 或 `view.value != ScreenplayViewState.result` → 返回。
     - `AppConfirmDialog.show(context, title: AppStrings.screenplayRegenerateConfirm(episodes.length))`；取消或 `!context.mounted` → 返回（什么都不变）。
     - `regenerating.value = true`；`try`：`await submitRegeneration()` 返回 `true` 且 `context.mounted` → `await load(context)`（作品已在“生成剧本中”，页面换成等待页）；`finally`：`regenerating.value = false`。
  3. **`submitRegeneration()`**（`@visibleForTesting`，返回 `Future<bool>`）：
     - 先 `await _saver.flush()`；返回 `false`（存不上，`_save` 已提示）→ 返回 `false`，不提交。
     - `project = _project`（flush 之后是最新版本）；`key = _regenerateKey ??= IdempotencyKey.create()`。
     - `final job = await DramaContentAPI.submitScreenplays(project.id, key, expectedRevision: project.revision, overwriteConfirmed: true)`（不带 `taskId`）。成功：`_regenerateKey = null`；`_overwriteConfirmedJobId = job.id`；返回 `true`。
     - `ApiException`：
       - 网络失败（`error.isNetworkError`）→ 保留 `_regenerateKey`，`CustomToast.fail(error.message, …)`，返回 `false`；
       - 其他 → `_regenerateKey = null`，`CustomToast.fail(error.message, …)`；`-560001` / `-560005` 时再 `await _refresh()`……注意 `_refresh` 只在 `CONFIRM_SCREENPLAYS` 时刷新编辑框；`-560005`（已有剧本任务在跑）要让页面进等待页，所以这两种情况都返回 `true`，让第 2 步去 `load(context)`（`load` 会按作品当前状态显示等待页或结果页）。其余返回 `false`。
  4. **应用时不问第二次**（改 `_show` / `_apply`）：`_show` 里有 `pendingCandidate` 时，如果 `candidate.jobId == _overwriteConfirmedJobId`，直接带覆盖应用（`DramaContentAPI.applyCandidate(…, 'apply-overwrite-$jobId', expectedRevision: project.revision, overwriteConfirmed: true)`），成功后 `_overwriteConfirmedJobId = null`；失败照 `_apply` 现有写法提示。其他情况（离开页面再回来、别的入口生成的）照现有 `_apply`（遇 `-560017` 弹 `creationApplyOverwrite` 再问一次——现有行为，不改）。
  5. **显示后默认选中第 1 集**：新剧本 `_fill` 时如果是这次重新生成的结果（第 4 步走了带覆盖应用），`selected.value = 0`。其他情况照现有。
  6. **按钮**（`view.dart` `_buildResult`）：`FlowPageHeader` 的 `action` 换成 `Row(mainAxisSize: MainAxisSize.min, children: [...])`：
     - `FlowGradientButton(label: AppStrings.creationRegenerate, outlined: true, onTap: controller.busy.value || controller.regenerating.value ? null : () => controller.regenerate(context))`；
     - `SizedBox(width: 16)`；
     - 原“设置画面”按钮不变，只把 `onTap` 改成 `controller.regenerating.value ? null : () => controller.confirm(context)`（`busy` 照旧）。
     - 只在 `result` 状态（`_buildResult`）里有；等待页、失败页不改。
- 不要做：不改等待页、失败页、剧本编辑区；不新增弹框；不改 `retry`；不加新颜色名；不改 `lib/apis/`。
- 验证：`flutter analyze`；F-03；J-01 截图对照设计图。
- 结果：`controller.dart` 加 `regenerating`、`_regenerateKey`、`_overwriteConfirmedJobId`、`regenerate(context)`、`submitRegeneration()`、`_applyConfirmed`，`_show` 遇到本页提交的那个任务的结果直接带覆盖应用并选中第 1 集；`view.dart` 结果页右上改成“重新生成”（描边）+ 间距 16 +“设置画面”，提交中两个都不可点。按计划写法，没有偏差。代码已写完；执行环境没有 Flutter，`flutter analyze` / `flutter test` 待用户在 Mac 上跑。

## 9. 风险与回滚

1. 重新生成失败时页面停在失败页，只能“重新生成”或“返回修改原文”，原剧本数据不删但看不到（和第一次生成失败一样，需求 4.20 已写明）。
2. 剧本手改过的作品，重新生成后如果中途离开页面再回来，应用结果时会再问一次“新生成的内容将覆盖你修改过的内容”（后端的手改标记在提交时不清掉；现有行为，本模块只在同一页面内省掉第二次）。
3. “已有剧本”类作品的“重新生成”是把原剧本重新拆分，不是按故事大纲重写（需求 4.20 已写明）。
4. 回滚：撤回 §7 列出的文件；没有数据和接口改动。
