# MakeCodePlanWord

一个人 + AI 做 App 的开发流程工作台：流程规则、模板、提示词、脚本，以及每个项目的工作区。

## 一个版本怎么走

```
产品 → 设计 → 技术规划 → 开发计划 → 开发 → 测试 → 上线 → 归档
```

项目根目录有一份 `当前产品文档/`（线上已完成的功能）；每个版本一个文件夹，按阶段放文档：

```
projects/{项目名}/
├── 当前产品文档/       线上已完成的功能
└── v2.2.0/
    ├── README.md        版本说明：到哪一步、文档在哪
    ├── 01-产品/         requirements-list.md、requirements.md、requirements-review.md、detection-feedback.md
    ├── 02-设计/         设计说明、设计计划
    ├── 03-技术规划/     完整的架构 / 接口 / 数据模型、技术方案
    ├── 04-开发计划/     开发计划
    ├── 05-测试/         测试
    └── 06-上线/         上线记录（含归档清单）
```

- **全量与增量分开**：`当前产品文档/` 是线上全量定义；版本 `01-产品/requirements.md` 集中描述本版增量。开发时结合两者阅读，未改功能不在版本目录重复复制；归档时只合并已上线的变化。
- **四份产品文档**：`requirements-list.md` 记录需求、R / AC 和来源；`requirements.md` 给开发使用；`requirements-review.md` 给用户核对和决策；`detection-feedback.md` 独立记录检测与复检。检测通过且用户明确确认才进入下一阶段，结构确认不等于业务批准。
- **工作区和代码分开**：文档都在 `projects/{项目名}/`；代码仓库根 `AGENTS.md` 写明工作区路径，AI 写代码时去那里读计划。
- **先计划后开发**：前后端一份技术方案、一份开发计划，审核后才写代码。
- **测试查到数据层**：验收标准和用例写清"存了什么、接口返回什么"；每个线上 bug 都补进回归集和高风险清单。
- **归档 = 增量合入当前产品文档 + 冻结 + git tag**。线上 bug 开 patch，只写一页修复单。

## 快速开始

| 我要…… | 看这里 |
|---|---|
| 知道每个阶段做什么、用哪个提示词 | `工作说明.md` |
| 了解整个流程 | `workflow/00-总流程.md` |
| 开一个新版本 | `prompts/提示词.md` P1 |
| 修线上 bug | `prompts/提示词.md` P10 |
| 新建项目 | `workflow/10-新项目初始化.md` |
| 把 v1 旧项目迁移过来 | `workflow/11-旧项目迁移.md` |
