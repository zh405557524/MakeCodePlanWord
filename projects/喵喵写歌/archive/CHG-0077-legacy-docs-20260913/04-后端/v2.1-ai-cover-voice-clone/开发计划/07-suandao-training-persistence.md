## 1. 功能定位与边界

实现算道首期 `sovits_train` 训练提交/查询，将厂家模型、配置和试听资源转存到平台，并创建可追溯音色模型版本和渠道绑定。厂家 URL 不能作为平台长期真源。

## 2. 适配范围

- 提交：算道 `/api/queue/music_tool`。
- 查询：`/api/midjourney/drawInfo4?id={providerTaskId}`。
- 主动轮询，不依赖 callback。
- 处理 request_id/task_id、状态、模型 URL、配置 URL、试听 URL和错误字段的兼容提取。

真实请求字段必须在编码前依据当前算道文档/测试环境确认；未确认字段保留配置或阻塞，不在文档中臆造。

## 3. 输入准备

- 训练素材必须已审核、owner 合法且满足质量规则。
- 通过现有受控访问服务生成短期厂家可读 URL。
- URL 设置短有效期并限制用途；不得记录到持久日志。
- 提交前写调用台账和 requestId，提交结果可关联。

## 4. 结果持久化

厂家成功后分别下载模型文件、配置文件和试听：

1. URL 安全校验、大小/超时/重定向限制。
2. 写入平台资源存储并记录真实类型、大小和校验值。
3. 模型/配置使用 INTERNAL；试听使用 OWNER 或发布官方音色所需权限。
4. 试听执行音频探测和内容审核。
5. 三类必需资源齐全、binding 有效且试听可播放/审核通过后，modelVersion 才 AVAILABLE。

## 5. 状态与恢复

- 厂家模型 ID、平台资源 ID 和绑定分别保存。
- 进程重启按 training task/provider task 继续查询或持久化，不重复训练。
- 厂家 ID 失效时 binding UNAVAILABLE；平台保存的模型文件能否重新导入目前不假设。
- 持久化阶段失败在策略内重试；厂家成功不等于训练任务成功。

## 6. 异常与日志

响应缺字段、未知状态、下载失败、内容类型不符、试听不可播放/审核拒绝均保存标准错误和厂家摘要。不得打印密钥、完整 URL或模型二进制。

SUBMIT_UNKNOWN 进入运维，不自动再次训练；明确厂家失败触发积分释放。

4. 实现模型/配置/试听下载和资源分类持久化。
5. 实现试听探测、审核、binding/modelVersion 状态收敛。

## 8. 测试要求

- 离线 fixture：正常、缺 task ID、未知状态、错误、资源缺失。
- URL 安全、超大、重定向、超时和格式不符。
- 重启后续跑、不重复提交、不重复创建资源/版本。
- 试听审核拒绝/不可播放时不 AVAILABLE。
- 厂家 ID 失效后 binding 不可用但历史作品不受影响。

- App 只获得受控试听，不获得厂家文件 URL。
- 真实试听播放成功前训练不判完整成功。
