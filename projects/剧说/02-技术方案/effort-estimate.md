## 0. 评估结论

在不生成 Figma、只按现有截图实现 MVP 的前提下：

### 0.1 AI 辅助开发 + 每天 8 小时口径

如果使用 AI 辅助开发，并且把 1 人天改成 8 小时有效工时，建议改用下面这版估算：

| 口径 | 结果 |
|------|------|
| 目标排期 | 3 周冲刺版，含支付与积分体系 |
| 期望总工时 | 约 35 人天 |
| 其中 Flutter 移动端 | 约 11 人天 |
| 其中后端 / 百度 VOD / 支付积分 | 约 19 人天 |
| 其中 QA / 联调 | 约 6 人天 |
| 3 周内置缓冲 | 约 2 到 3 人天 |
| 团队建议 | 1 Flutter + 1 后端 + 0.5 QA 并行，后端需优先做支付/VOD |
| 单人全栈 + AI 串行排期 | 约 6 到 7 周 |
| 纯演示版，不接真实百度 VOD / 短信 | 约 2 到 3 周 |

AI 可以明显压缩页面、组件、接口样板、本地状态和文档对齐时间；但百度智能云 VOD 联调、上传异常、回调、真机权限、弱网、视频播放和最终验收仍需要人工实测，所以不能按“AI 直接减少一半以上”来算。

### 0.1.1 3 周冲刺前提

要把完整 MVP 压到 3 周，需要满足以下前提：

- 百度智能云 VOD 账号、AK/SK、上传方式、智能任务模板、回调地址在第 1 天准备好。
- 支付渠道、商户号、沙箱环境、回调域名、验签密钥在第 1 天准备好。
- 短信登录可先接通用服务或临时 mock，不能卡主链路。
- 先交付内部验收版，不包含应用商店上架、复杂会员、优惠券、分销、财务后台、退款后台。
- 异常态先覆盖关键场景：上传失败、生成失败、任务超时、重复点击；更细的弱网恢复和后台续传放到后续迭代。
- 支付先覆盖最小闭环：套餐、下单、回调验签、到账、重复回调幂等、支付成功后积分入账。
- UI 以截图还原为准，不再新增 Figma 和复杂动效。

### 0.2 移动端单独估算

如果只看 Flutter 移动端，不含后端开发：

| 移动端范围 | AI 辅助后估算 |
|------------|---------------|
| 工程初始化、目录、路由、主题、网络、本地存储 | 0.25 到 0.5 天 |
| 静态 UI 版：首页、作品、我的、上传页、弹层，可点击跳转 | 2.5 到 3.5 天 |
| 完整移动端交互版，接口使用 mock | 4 到 5.5 天 |
| 接真实后端，含上传、任务状态、播放入口 | 8 到 10 天 |
| 真机适配、异常态、弱网、权限、回归修复 | 另加 1.5 到 2 天 |

在 AI-first 模式下，这类任务应该按小时计，不应该按天计。

### 0.3 解释

这个 App 看起来只有 4 个主页面，但实际开发量集中在“视频生产链路”：

- 视频选择、缩略图、时长读取、删除、多视频数量限制、权限和弱网处理。
- 百度 VOD 上传、媒资 ID 回写、生成任务、回调、轮询、播放地址。
- 积分预估、冻结、扣减、失败退回、充值到账、作品保留 7 天。
- 支付订单、回调验签、重复通知幂等、到账补偿。
- 登录、作品列表、我的、设置、举报、算法备案这些虽小，但都要可点通。
- 真实 App 还要处理上传失败、生成失败、任务卡住、重复点击、退出后恢复等异常态。

如果只是做“能点的前端样子”，会快很多；如果要真的能上传并生成视频，时间主要花在联调和异常处理。

### 0.4 传统人工口径仅作参考

传统人工开发、不使用 AI、按 6 小时有效工时估算时，总工时约 80 人天。

- AI 辅助开发口径：1 人天 = 8 小时有效工时。

- App 范围为首页、作品、我的、短剧生产/视频上传主链路，以及截图中的登录、设置、举报、算法备案和底部弹层。

- 百度智能云账号、VOD 服务、模板、回调域名和测试素材可在开发第 1 周提供。

## 5. 关键路径与并行度分析

关键路径：

1. `T-B001 -> T-B010-01~05 -> T-B011-01~07 -> T-QA004`
2. `T-B001 -> T-B003 -> T-B004 -> T-B005 -> T-QA001 -> T-QA002 -> T-QA003`
3. `T-F001 -> T-F006 -> T-F008 -> T-F009 -> T-QA001 -> T-QA002 -> T-QA003`

可并行项：

- 首页、我的、作品空态可与后端底座并行。
- 登录页 UI 可先 mock，短信服务联调后替换真实接口。
- 参数弹层可先接本地静态配置，后续切到 `T-B007`。
- 支付前端可先接 mock 订单，后端回调验签完成后替换真实沙箱。
- QA 可在第 2 周开始测页面、登录和 mock 主流程，不必等百度 VOD 全部完成。

主要阻塞：

- 百度 VOD 上传和智能生成任务没有跑通前，无法验收真实“立即生成”闭环。
- 支付渠道资料、商户号、沙箱、回调验签如果第 1 周未准备，会直接影响 3 周目标。
- 回调域名、任务模板、播放鉴权如果第 1 周未准备，会直接推迟 Alpha。

## 7. 风险缓冲

3 周冲刺版不再单独拉长 20% 标准缓冲，而是在第 2 到第 3 周内置约 2 到 3 人天风险缓冲，并把百度 VOD 相关任务作为重点风险跟踪。

缓冲原因：

- 百度 VOD 的智能视频任务模板、参数映射、回调字段需要控制台实测。
- 支付回调验签、重复回调、到账补偿必须用沙箱或真实测试环境验证。
- 移动端视频上传在权限、弱网、后台、超时场景中容易返工。
- 当前只有截图，没有完整有数据态/错误态/结果页设计，需要开发补齐。

若第 1 周无法拿到百度智能云测试账号、AK/SK、VOD 模板、支付商户资料和回调环境，3 周目标风险较高，建议改为 4 到 5 周。
