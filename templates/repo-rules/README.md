# 代码仓库编码规范模板

这里是**新项目用的模板**。新建仓库时，把对应技术栈的目录复制到仓库的规范目录（建议 `.cursor/rules/`，和现有项目一致），按项目实际修改，再在仓库根 `AGENTS.md` 的「规范索引」登记。

**复制进仓库之后，以仓库里的规范为准。** 这里的模板之后再改，不会自动同步到已有项目；AI 编码时也不读这里。

## Flutter（`flutter/`）

2026-11-16 起以喵喵漫剧手机端仓库实际在用的规则为底，去掉项目专属内容后的通用版（旧版在 `_backup/20261116-repo-rules-flutter-旧版/`）。文件是 `.mdc`（带 Cursor 的 frontmatter），整个目录连同 `templates/` 一起复制到仓库 `.cursor/rules/`。

| 文件 | 内容 |
|---|---|
| `00-规则总索引.mdc` | 铁律、任务分派表、通用完成标准、规则优先级。任何代码任务先读 |

| `02-编码约定.mdc` | 命名、导入、注释、错误处理、不阻塞界面线程、验证 |
| `03-状态管理.mdc` | GetX：`.obs` + `Obx`，Controller / 模块 Store / 公共 Service 分工 |
| `04-路由导航.mdc` | go_router：路由名、注册、传参、守卫 |
| `05-界面实现.mdc` | 设计输入、页面骨架、适配、主题、资源、弹框、提示、状态完整性 |
| `06-多语言.mdc`、`07-依赖管理.mdc` | 多语言、依赖分层与引入 |
| `10-项目初始化.mdc` | 只在新建工程时用 |
| `11`～`15` | 任务剧本：新功能、界面对稿、问题修复、业务逻辑修改、重构（一次只读一个） |
| `16-先规划再编码.mdc`、`20-编码工作流程.mdc`、`21-测试用例与执行.mdc` | 规划与执行的硬性规则、编码阶段流程、测试用例写法。计划模板和流程以工作台 `workflow/04`、`05`、`06` 为准 |
| `90-项目专属规则.mdc` | **新项目只改这一份**：项目身份、选型、令牌、复用入口、页面索引、例外 |
| `templates/` | `feature/` 页面三件套示例；`scaffold/` 旧版脚手架，只作参考 |

## 和 v1 相比去掉了什么

- v1 的 `09-大功能先规划再编码`、`10-编码工作流程`、Flutter `11-测试规则`、`13/14 编码索引` 由工作台 `workflow/04-开发计划.md`、`05-开发.md`、`06-测试.md` 取代，原文件在 `legacy/v1/`。
- 文件开头的 Cursor frontmatter（`description` / `globs` / `alwaysApply`）已删除。现在由仓库根 `AGENTS.md` 的规范索引决定什么时候读哪份规范，Codex、Claude Code、Cursor 都能用。
