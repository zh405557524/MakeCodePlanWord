# 09 新项目初始化

目标：新项目从第一天起就用 v2 结构：工作台里有项目文档目录，代码仓库里有 `AGENTS.md` 和编码规范，然后按总流程开 `v1.0.0`。

工作区和代码分开：文档目录在工作台 `projects/{项目名}/doc/`，代码仓库只放代码和规范。

## 步骤

1. **登记项目**：在工作台 `workspace-registry.json` 加一项，写上 `name`、`aliases`、`appRepo`、`backendRepos`，`docRoot` 填 `/Users/soul/work/MakeCodePlanWord/projects/{项目名}/doc`，`flow` 填 `"v2"`。

2. **生成文档骨架**：
   ```bash
   /Users/soul/work/MakeCodePlanWord/scripts/init-doc.sh /Users/soul/work/MakeCodePlanWord/projects/{项目名}/doc {项目名}
   ```
   脚本会复制 `templates/doc/`（不含版本模板），已存在的文件不会被覆盖。

3. **写仓库入口**（有代码仓库后）：把 `templates/repo/AGENTS.md` 和 `templates/repo/CLAUDE.md` 复制到仓库根目录，填写项目信息、**文档目录的绝对路径**、目录结构、硬规则、规范索引和验证命令。后端是多 App 共用的，在后端仓库 `AGENTS.md` 里加一节写明这个 App 的文档目录。

4. **放编码规范**：把 `templates/repo-rules/` 下对应技术栈的规范复制到仓库的规范目录（建议 `.cursor/rules/`）：
   - Flutter App：`templates/repo-rules/flutter/`
   - Java 后端：`templates/repo-rules/java/`
   - 复制后按项目实际情况修改。和项目无关的规范删掉；项目特有的规范（业务复用、支付、内容资源等）新增文件，并登记到 `AGENTS.md` 的规范索引。
   - **从这一刻起，这个仓库的规范以仓库里的为准**，工作台模板之后的修改不会自动同步过来。

5. **搭工程骨架**：按规范目录下 `init/` 的初始化规范搭基础结构（Flutter 见 `01-项目初始化规则.md` 和 `task-project_init.md`；Java 见 `01-项目初始化规则.md`）。这一步本身也写一份小的 `plan.md`，审核后执行。

6. **开 v1.0.0**：
   ```bash
   /Users/soul/work/MakeCodePlanWord/scripts/new-version.sh /Users/soul/work/MakeCodePlanWord/projects/{项目名}/doc v1.0.0
   ```
   然后从 `01-版本规划.md` 开始。

## v1.0.0 的特殊之处

- 基线是空的，`changes.md` 里所有条目都是 `[新增]`，仍然按模块组织，另写 `00-overview` 一节（见 `02`）。
- 技术架构是全新的，在版本文件夹里写 `tech-design.md`（技术栈、目录、分层、关键流程、环境与配置、三方服务），`plan.md` 引用它。发布时合并成文档目录的 `tech/architecture.md`。
- 第一次上架时看 `参考/首次上架清单.md`。

## 完成标准

- [ ] 文档目录 `projects/{项目名}/doc/README.md` 填好了项目信息
- [ ] 仓库根目录有 `AGENTS.md` 和 `CLAUDE.md`，`AGENTS.md` 写明了文档目录的绝对路径，规范索引里的文件都存在
- [ ] `workspace-registry.json` 已登记，`flow` 为 `"v2"`
- [ ] 用 Codex / Claude Code 在仓库里新开会话，问"这个项目的编码规范是什么、开发计划在哪"，AI 能答出 `AGENTS.md` 里的硬规则和文档目录
