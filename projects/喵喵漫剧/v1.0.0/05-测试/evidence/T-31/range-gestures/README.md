Android 原实现仅在源帧率不同时重采样。非整帧裁剪即使源为24fps，824ms成片也可能只有19帧，实际23.058252fps，原校验正确拒绝。现在只在需要转换或裁剪不对齐帧时钟时重采样，并让MP4尾帧保留完整帧期。保存的时间轴、音轨和PCM仍为824ms，视频结束833ms符合既有一帧容差；帧率/时长校验均未放宽。

保留了五次前期尝试：工具入口等待失败、导航未就绪中止、首次真实导出失败、诊断代码编译失败，以及明确23.058252fps的诊断复跑。它们均不计最终通过；记录见 [attempts](attempts/)。编译失败时留下的旧APK明确标记为无效，不冒充新构建。自有安装、锁、转发/反向转发、宿主源服务器均已清理，原有连接保持；全程未访问相册。

源为自建蓝色视频及440/880Hz双轨，生成命令和摘要在 [sources.json](sources.json)。App使用原生引擎，FFmpeg只用于宿主造样片和独立解码。原件、APK、原始日志保存在本地忽略的`originals/`；公开压缩日志已去除本地VM票据及Bearer。失败后不改判结果或降低阈值。

仅为TC-15-04/05、TC-18-01/08和TC-21-02追加部分证据；原步骤、预期及全部186条状态保持，仍10通过/173部分/3未执行。47项仍7完成/38进行中/2外部。其他机型、iOS真机、真实模型/OSS、长片性能和最新Figma继续待验，阶段保持开发。
