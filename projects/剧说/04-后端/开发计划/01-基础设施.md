## 1. 功能定位与边界

本模块负责 Java 后端工程的基础设施：Gradle 工程、Spring Boot 启动、配置分层、统一响应、异常处理、错误码、日志、Trace、Redis、Flyway、MyBatis-Plus 基础配置和测试基线。

不包含具体业务接口实现，不接入真实百度 VOD、支付或短信供应商。

## 3. 接口契约

基础设施模块不提供业务接口。可提供健康检查：

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/actuator/health` | 否 | Spring Boot Actuator 健康检查 |

统一响应：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "traceId": "string"
}
```

## 4. 数据表与迁移

首个迁移脚本创建基础业务表骨架：

- `users`
- `sms_codes`
- `refresh_tokens`
- `point_accounts`
- `point_ledgers`
- `membership_plans`
- `user_memberships`
- `payment_orders`
- `media_assets`
- `creation_drafts`
- `generation_tasks`
- `works`
- `provider_events`
- `invite_records`
- `feedbacks`
- `app_configs`

迁移要求：

- 所有表包含 `created_at`，需要更新的表包含 `updated_at`。
- 状态字段统一 `VARCHAR(32)`。
- 外部供应商 ID 字段使用 `VARCHAR(128)`。
- 幂等约束必须加唯一索引，如 `point_ledgers(biz_type, biz_id, operation)`、`provider_events(provider, provider_event_id)`。

---

## 5. 业务规则

- `traceId` 每次请求生成并返回。
- 全局异常统一转换为 `ApiResponse`。
- 业务异常使用 `BizException(ErrorCode, message)`。
- Redis 不作为最终事实来源，只用于短期锁、缓存、验证码和幂等。
- Flyway 必须能在空数据库完整执行。
