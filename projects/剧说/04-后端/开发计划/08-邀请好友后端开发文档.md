## 1. 后端范围

本任务在既有邀请模块基础上扩展完整邀请收益闭环：

- 邀请链接注册并自动绑定邀请关系。
- App 内手动绑定邀请人。
- 好友注册后给直接邀请人发放 `10` 积分，后台可配。
- 好友首次开通会员后给直接邀请人生成现金收益；符合后台配置的上级可获得一层间接收益。
- 用户可查看收益、发起提现、查看提现记录。
- 后台可配置邀请规则并处理提现审核。
- 后端提供公开简单邀请注册落地页。

## 6. 关键请求与返回

### 6.1 绑定邀请人

请求：

```json
{
  "inviteCode": "ABC123"
}
```

错误场景：

- 邀请码不存在：`BAD_REQUEST`
- 绑定自己：`BAD_REQUEST`
- 当前用户已绑定：`BAD_REQUEST`

### 6.2 邀请概览

返回字段：

- `inviteCode`
- `inviteLink`
- `ruleText`
- `invitedCount`
- `memberCount`
- `rewardPoints`
- `agentLevel`
- `directCommissionRate`
- `directInviteCount`
- `indirectCommissionEnabled`
- `indirectCommissionRate`
- `totalEarningsCents`
- `withdrawableCents`

### 6.3 会员返佣计算

直接邀请示例：A->B。

- B 注册后，A 获得 `10` 积分。
- B 第一次开通会员时，A 获得直接返佣。
- A 为个人代理 1 级时返 `10%`，2 级时返 `20%`，3 级时返 `30%`。
- B 续费会员、再次开通会员、充值积分都不再给 A 返佣。

间接邀请示例：A->B->C。

- C 注册时，A 没有注册送积分。
- C 第一次开通会员时，如果 A 的 `indirect_commission_enabled=true`，A 获得固定 `10%` 间接收益。
- 间接收益不读取 A 的个人代理等级。

一层限制示例：A->B->C->D。

- D 第一次开通会员时，C 获得直接返佣。
- B 如开启间接收益资格，获得固定 `10%` 间接收益。
- A 超过一层间接关系，没有收益。

### 6.4 发起提现

请求字段：

- `amountCents`
- `channel`
- `accountNo`
- `agreementAccepted`

校验：

- 金额必须大于等于最低提现金额。
- 金额不能超过可提现收益。
- 协议必须勾选。
- 账号不能为空。

## 7. 状态流转

| 对象 | 状态流转 |
|------|----------|
| 邀请关系 | `UNBOUND -> BOUND` |
| 注册积分 | `PENDING -> REWARDED / DISABLED / FAILED` |
| 直接会员返佣 | `PENDING -> SETTLED / SKIPPED / FAILED` |
| 间接会员返佣 | `PENDING -> SETTLED / SKIPPED / FAILED` |
| 提现成功 | `PENDING_REVIEW -> APPROVED -> PAID` |
| 提现驳回 | `PENDING_REVIEW -> REJECTED` |
| 打款失败 | `APPROVED -> PAY_FAILED` |

## 8. 事务与幂等

- 邀请绑定与注册积分必须在同一事务中完成。
- 注册积分通过 `PointsService` 写入 `INVITE` 类型流水，不能直接改积分余额。
- 注册奖励积分默认 `10` 积分，并通过后台规则读取。
- 会员返佣由支付成功回调触发，仅处理会员商品，且只处理该用户第一次开通会员订单。
- 直接会员返佣以 `sourceUserId + DIRECT_MEMBER_COMMISSION` 保证不重复结算。
- 间接会员返佣以 `sourceUserId + INDIRECT_MEMBER_COMMISSION` 保证不重复结算。
- 支付回调重复时，同一订单可同时生成直接与间接两条账本，但每类账本不能重复。
- 个人代理等级只影响直接返佣比例：1 级 `10%`，2 级 `20%`，3 级 `30%`。
- 个人代理 2 级在直邀人数达到 `10` 后对后续被邀请人生效；个人代理 3 级在直邀人数达到 `30` 后对后续被邀请人生效，历史已结算订单不追溯。
- 间接收益只看关系层级和后台开关：固定 `10%`，只穿一层，不受个人代理等级影响。
- 提现申请会冻结可提现收益。
- 驳回或打款失败退回可提现余额。
- 打款成功只改提现和账本状态，不删除历史记录。

## 9. 后台审核规则

- 审核通过只能从 `PENDING_REVIEW` 进入 `APPROVED`。
- 驳回只能从 `PENDING_REVIEW` 进入 `REJECTED`。
- 标记打款成功只能从 `APPROVED` 进入 `PAID`。
- 标记打款失败只能从 `APPROVED` 进入 `PAY_FAILED`。
- 每次后台操作必须记录操作者、时间和备注。
- 开启 / 关闭用户间接收益资格必须记录操作者、时间和备注。

## 10. 测试要求

- 邀请链接注册自动绑定邀请人。
- App 内绑定邀请码覆盖无效码、自邀、重复绑定。
- 注册奖励积分默认 `10` 积分且幂等，不重复发放。
- 直接邀请会员订单首次支付成功后按个人代理等级生成 `10% / 20% / 30%` 返佣。
- 个人代理等级升级后只影响后续被邀请人的首次会员订单，不追溯历史收益。
- 开启间接收益资格的用户，可对一层间接用户首次会员订单获得固定 `10%` 收益。
- A->B->C->D 中，D 首次开通会员时 C 有直接收益，B 可有间接收益，A 无收益。
- 续费会员、再次开通会员、充值积分都不产生返佣。
- 提现申请冻结可提现金额。
- 驳回和打款失败退回可提现余额。
- 打款成功不退回余额。
- 后台审核接口覆盖成功和非法状态流转。
