# 支付方式与支付宝 Web/WAP 支付验收用例

## 范围

- 变更编号：CHG-0002、CHG-0005
- 版本：v0.3.2
- 平台：Android；iOS 仅回归原有 Apple IAP
- 后端/API 改动：无
- 数据/配置改动：无
- 数据库改动：无

## P0 用例

### 支付方式入口

1. 分别进入 Android 积分充值页和会员购买页。
2. 确认“支付宝 Web/WAP”下方显示“微信支付 Web/WAP”，且支付宝默认选中。
3. 点击微信行，确认提示“微信支付暂未开通”，选中状态仍停留在支付宝。
4. 确认点击微信不会创建订单、不会调用微信支付接口、不会拉起微信。
5. 在 iOS 进入对应页面，确认不展示 Android Web 支付渠道，Apple IAP 流程保持不变。

### 已安装支付宝时自动拉起 App

1. 分别从会员购买、积分充值和待支付订单进入支付宝支付。
2. 点击“立即购买/充值”后，确认只创建一次订单并直接显示居中“支付处理中”弹框。
3. 确认不再出现订单、金额、渠道和“确认支付”二次确认底部弹层。
4. 确认弹框先显示“正在前往支付宝...”，系统直接进入支付宝 App，不出现全屏 WAP 支付页。
5. 弹框显示期间触发返回键或快速重复点击，确认无法关闭且不会重复加载 WAP form。
6. 在支付宝完成支付并返回 App。
7. 确认弹框显示“正在查询订单状态...”，只执行一轮有界查询，成功后关闭并刷新会员权益、积分或订单状态。

### 未安装或无法拉起支付宝

1. 在未安装支付宝的 Android 真机发起支付。
2. 确认提示“请先安装支付宝 App”，支付中弹框关闭，用户仍停留在原购买页面。
3. 分别模拟 WAP form 加载失败、外部启动异常及限定时间内未捕获 `alipay/alipays`。
4. 确认弹框均关闭并显示对应重试提示，不进入全屏 WAP 页面，用户可重新发起支付。

## P1 用例

### 支付取消、失败和待支付

1. 拉起支付宝后分别执行成功、取消、失败或不完成支付并返回。
2. 确认每次生命周期恢复只发起一轮订单查询，不会再次拉起支付宝。
3. 成功、取消或失败订单返回来源页并展示最新状态。
4. 持续待支付订单在查询结束后关闭弹框，并由来源页提示稍后查看或重新支付。

### HTTPS 回调与重复操作

1. 让隐藏 WebView 访问支付宝成功回调 HTTPS 地址。
2. 确认回调地址触发一次订单查询，普通 HTTPS 导航仍由隐藏 WebView 处理。
3. 同时触发资源协议和导航协议回调，确认支付宝外部 App 只启动一次，且自定义协议不会继续在 WebView 导航。

## P2 回归

- 普通网页继续使用项目原有 WebView，未受支付隐藏 WebView 影响。
- Apple IAP 的购买、恢复购买及订单确认流程保持不变。
- 会员权益、积分到账与订单“继续支付”的来源页刷新逻辑保持不变。
- 支付路由关闭时释放隐藏 WebView、定时器和生命周期监听。
