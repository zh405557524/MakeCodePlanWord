# 喵喵穿搭可执行测试用例明细（优先批次）

> 版本：v0.1.0-test-design.4；对应 [QA 总计划](qa-plan.md) 的既有 ID，不另造一套统计口径。  
> 当前阶段：02 需求文档生成 / `waiting_review`；第15阶段仍为 `pending`。本文件细化原152个编号中的46个，剩余106个仍是检查点；不表示下列用例已正式执行。  
> 规则来源：现有 App/TEST 实测可观察行为用于回归期望；PRD 尚未确认的穿搭产品决策仍标 `blocked_by_TBD`，不能靠“当前实现如此”自动通过。

## 1. 通用执行记录与安全边界

每条用例执行前记录 App 包名、版本/commit、后端环境与版本、设备/系统、网络、测试用户编号、执行时间；执行后记录实际结果、余额/流水或任务/作品 ID（只用脱敏 ID）、截图/日志路径、PASS/FAIL/BLOCKED 和关联缺陷。成功、失败、取消、重试需分别记录任务 ID，不能只看 Toast。换账号、删除、模拟支付、重复回调、扣积分等操作仅对 TEST 数据进行；没有安全的失败注入或测试沙箱时标 `blocked_by_env`，不得使用生产订单或他人数据代替。

本批素材见 [素材说明](test-materials/20260928/README.md)。下文 `A脸`=`person-a-face.png`，`A全身`=`person-a-full-body.png`，`B全身`=`person-b-full-body.png`，`白衬衫`=`clothing-white-shirt.png`，`牛仔裤`=`clothing-blue-jeans.png`，`碎花裙`=`clothing-floral-dress.png`，`平铺四件`=`clothing-mixed-flatlay.png`。负样本为 `invalid-face-obscured.png` 和 `invalid-two-people.png`。现有素材不覆盖超20MB、损坏、HEIC、低清、未成年人等情况，须另备且不得虚报通过。

测试数据隔离：T1 空档案/空衣橱且可用积分充足；T2 已有档案与单品；T3 积分不足；T4 临近5个档案/100件衣物上限；T5 会员即将到期且已有资产；T6 有可控 AI 失败/超时/重复回调能力；T7 有支付沙箱和可控回调。T1～T7 是数据特征，不是已经创建的账号。每次执行前核对当前余额和资产数量；每次执行后清理本轮生成的 TEST 数据或记录不可清理原因。

判定口径：`已实测`仅指 [Android 素材记录](material-test-execution-record.md) 中明确列出的那一小段观察；同一大用例尚未覆盖的步骤仍为 `not_run`。涉及首次免费、取消/失败退款、照片/作品删除、报告分享等未决规则，先记录现状，待决策后补最终预期再判 PASS/FAIL。
