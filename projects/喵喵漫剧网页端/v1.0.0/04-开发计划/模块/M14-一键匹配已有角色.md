## 3. 现状摘要

1. 页面：`lib/pages/project_assets/`（`part` 聚合，入口 `index.dart`）。汇总条在 `view.dart` 的 `_SummaryBar`：右侧依次是“批量生成本集描述 N”（有缺描述时才有）、“批量生成本集图片 N”、图片模型下拉。描边按钮组件 `_OutlineButton`（`icon`、`label`、`enabled`、`onTap`）。
2. 控制器 `ProjectAssetsController`（`controller.dart`）：`projectId`、`episodeId`、`overview`、`bindings`（当前集素材，`DramaAssetBinding`，含角色、场景、道具）、`mediaUrls`、`localImports`、`refreshEpisode()`、`importFromLibrary()`。
3. **卡片上“导入角色 / 场景 / 道具”的换图写法就是本模块确认时要用的**：`lib/pages/asset_picker/controller.dart` 的 `confirm()` 里 `binding != null` 分支——先 `DramaAssetsAPI.impact(binding)`，再 `DramaAssetsAPI.replaceImage(binding, IdempotencyKey.create(), impact: impact, sourceAssetId: asset.id, sourceImageVersionId: image.id)`。资产库候选的过滤也照它：`asset.canImport && asset.imageAvailableAt(now)`。
4. **候选只从资产库取**（接口约束，总览第 3 行）。`GET /api/drama/assets?scope=PERSONAL&kind=…` 不带 `personalOnly`、不带 `originProjectId` 时，返回本人这个类型的全部资产库素材：通用资产（`originProjectId` 为空）+ 作品资产（`originProjectId` = 来源项目，`originProjectName` = 项目名快照）。本项目里生成过图的素材，后端会自动存一份到资产库的作品资产（`originProjectId` = 本项目），所以“本项目”的素材也在这里；**本地上传到本项目的图不进资产库，匹配不到**（已在需求 4.17 注明）。每页最多 100 条（后端 `pageBounds`）。
5. 素材字段（`lib/models/data/drama_asset.dart` 的 `DramaAsset`）：`id`、`name`、`description`、`kind`（`ROLE` / `SCENE` / `PROP`）、`appliedImage`（`id`、`media.resourceId`）、`canImport`、`originProjectId`、`originProjectName`、`imagePhase`、`imageAvailableAt(now)`。本集素材是 `DramaAssetBinding`（`id`、`asset`、`revision`）。类型文字用现有 `AppStrings.assetsKindLabel(kind)`（角色 / 场景 / 道具）。
6. 当前项目名：`DramaProjectsAPI.get(projectId)` 返回的 `DramaProjectDetail.name`。
7. 可复用：`AssetImagePreviewDialog.show(context, name:, imageUrl:)`（`widgets/image_preview_dialog.dart`，看大图）；`NetImage`（网络图片）；`showThemeDialog`（`lib/widgets/theme_rebuilder.dart`）；`FlowGradientButton`（主按钮）；`GenerationConfirmDialog` 的弹框外观（渐变底、圆角 20、关闭按钮 `assets/images/dialog_close.png` + `controlIconFilter`）；删除图标用现有 `AppAssets.iconDelete`（垃圾桶，可着色）。
8. 参考写法：弹框照 `lib/components/generation_confirm_dialog.dart`（`StatefulWidget` + 自己的 State）；控制器调接口、`CustomToast` 照 `ProjectAssetsController.uploadLocal`。

  3. 文字处理（常量写在文件顶部并加注释）。测试文件访问不到私有函数，对外各留一个公开的静态方法给测试用（加 `@visibleForTesting`）：`AssetMatcher.normalize(s)`、`AssetMatcher.projectKey(s)`、`AssetMatcher.similarity(a, b)`；页面代码不要用这三个方法：
     - `_norm(s)`：去首尾空白；去掉所有空白和这些符号 `·•・.-_—()（）[]【】「」《》"'“”‘’，,。:：;；!！?？/\\`；英文转小写。
     - `_dice(a, b)`：字符二元组（bigram）Dice 系数 = 2 × 共同二元组个数 ÷ (a 的二元组数 + b 的二元组数)，二元组按多重集计数；任一方长度 < 2 时改用单字集合计算；任一方为空返回 0。
     - `_projectNorm(s)`：**先在原文上**去掉带括号的“上 / 中 / 下”（正则 `[（(\[【]\s*[上中下]\s*[)）\]】]`），再 `_norm`，再依次去掉：`第[0-9一二三四五六七八九十百零两]+[部季集篇章卷册期]`、`(续集|续篇|前传|后传|番外|完结篇)`、末尾的 `[上中下][部篇集]`（单独一个“下”字不去——否则《天下》会变成《天》）、末尾的数字。
  4. 三个打分：
     - 名称 `nameLevel`：`na = _norm(本集素材名)`、`nb = _norm(候选名)`，任一为空 → 0；`na == nb` → 2；否则按类型：
       - **角色**：较短的长度 ≥ 2 且较长的包含较短的，或 `_dice(na, nb) >= 0.6` → 1；但先排除“关系称呼”（D-54）：较长的名字以较短的名字开头、多出来的部分 `rest` 以“的”或称谓表 `kKinshipWords` 里的词开头 → 直接 0。称谓表：`妈妈、妈、母亲、娘、爸爸、爸、父亲、爹、爷爷、奶奶、外公、外婆、姥姥、姥爷、哥哥、哥、姐姐、姐、弟弟、弟、妹妹、妹、儿子、女儿、孙子、孙女、老公、老婆、丈夫、妻子、媳妇、男友、女友、男朋友、女朋友、叔叔、阿姨、舅舅、姑姑、同学、同事、朋友、助理、秘书、司机、保镖、手下、徒弟、师父、师傅、老师、学生`。
       - **场景、道具**（D-55，更严）：只看 `_dice(na, nb) >= 0.6` → 1；**“包含”规则不用**（“客厅”和“江敏家客厅”不算相近）；“关系称呼”规则不适用。
       - 名称归零的一对仍然可以因为“描述相近”过门槛（那时标签只有“描述相近”）。
     - 项目 `projectWeight` / `projectKind`：候选 `originProjectId` 为空 → `general`，0；等于 `projectId` → `self`，1.0；否则 `pa = _projectNorm(projectName)`、`pb = _projectNorm(originProjectName ?? '')`：两者非空且相等 → `similar`，0.8；`_dice(pa, pb) >= 0.5` → `similar`，`0.4 + 0.4 × dice`；否则 → `other`，0.1。
     - 描述 `descScore = _dice(_norm(本集描述), _norm(候选描述))`，任一为空为 0；`descSimilar = descScore >= 0.5`。
  5. 门槛：`nameLevel >= 1 || descSimilar`，不满足的不算候选。
  6. 同一档里的分：`score = projectWeight × 10 + descScore × 3`。排序键：`nameLevel` 降序 → `score` 降序 → 候选 `id` 升序 → 本集原顺序（保证结果稳定）。三种类型混在一起排，不分组。
  7. 一对一分配：把所有过门槛的（本集素材，候选）对按排序键排好，从前往后取：本集素材还没分到、候选还没被用过，才分配。结果 `matches` 就按这个顺序；没分到的本集素材进 `unmatched`。
  8. 门槛和权重的数字都写成命名常量（`kNameDiceThreshold = 0.6`、`kNameContainMinLength = 2`、`kDescThreshold = 0.5`、`kProjectDiceThreshold = 0.5`、`kProjectWeightScale = 10`、`kDescWeightScale = 3` 等），注释写“R-34 模糊匹配，2026-11-19；要调宽严只改这里”。

     - 先 `DramaAssetsAPI.episodeList(当前集 id)` 读一次最新的本集素材；读失败时每一项都记失败（原因 = `error.message`）并返回。

     - 不调用任何生成、报价接口；不改名称、描述、音色（`replaceImage` 只换图）。
     - 知道一下（现有接口的行为，不用改）：`replaceImage` 固定按“共用的各集一起改”提交（`_sharedScope`），所以这个素材如果和别的集共用，别的集也会一起用上这张图。这和卡片上“导入”的效果一样。

## 9. 风险与回滚

- 资产库素材很多时：每个类型读满 10 页（1000 个）就停，三个类型最多 30 页，加载可能要几秒；超过的记日志，不报错。
- 模糊匹配会有误配：门槛偏严（D-53），场景、道具更严（D-55，不用“包含”规则），且列表可删；数字都在 `asset_matcher.dart` 顶部常量，调宽严只改那里。
- 场景、道具不用“包含”规则后，“医院”和“市第一医院”这种实际是同一个地方的也配不上，靠用户自己导入；以后要放宽只改 `_nameLevel` 里场景、道具那一支。
- 本地上传到本项目的图不在资产库里，匹配不到（已在需求注明）。
- 匹配来的图沿用来源图的到期时间（后端 `importReplacement` 原样带过来）：来源图快到期时，匹配上的图也会很快到期。本模块不处理，只过滤已经到期的。
- 角色名称“包含”规则的已知误配：已加“关系称呼不算相近”（D-54）。称谓表之外的写法（例如“小白他妈”“小白家的狗”）仍可能误配，靠列表里的删除图标处理；要补词只改 `kKinshipWords`。
- 回滚：删掉新增的 4 个文件和图标，撤回 `view.dart`、`controller.dart`、`index.dart`、`assets.dart`、`zh_cn.dart` 的改动；没有数据和接口改动。
