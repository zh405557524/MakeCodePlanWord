## 0. 一页结论

- **2026-11-16 起 `/api/drama/**` 要改一部分**（分镜逻辑调整，D-33～D-40，接口 K-01～K-08）：素材分析不再拆片段；进入某一集的分镜前生成这一集的片段 + 视频描述词（按集，与手机端一致）；新增“单个片段重新生成描述”；检测问题返回前端、不判失败。其余漫剧接口仍是手机端在用的那一组（索引见 `api.md` §5），不改。
- **后端代码要改 4 处**（都写进单独的后端开发计划）：
  1. `X-OS-Type` 请求头多接受 `web`、`windows`、`mac`（R-06）。
  2. 新增 3 个密码接口 + 网页端新建账号的 IP 限制；短信登录在网页端多 1 种失败（R-11、R-24）。
  3. 支付宝网页支付在电脑上改用“电脑网站支付”的内嵌二维码；手机上的行为不变（R-04）。
  4. 漫剧分析与片段流程（B-10）：剧本 → 分集时定好每集素材；素材分析只整理素材；确认某一集素材后生成这一集的片段、新增单个片段重新生成描述；检测结果返回前端；剧集阶段改为 素材 → 片段 → 视频。**手机端本版一起做最小适配（R-32、M11），跨端改动清单见 §6.1。**
- **数据库要加 1 张表**：`user_password_credentials`（只存密码的加密结果）。`users` 表不动。需要你同意（后端红线：库结构变化要用户同意）。 B-10 给漫剧表加可空 JSON 字段（每集素材清单、片段检测问题）和约束值（剧集阶段 `SHOTS`、任务种类 `SHOT_DESCRIPTION`），追加到未在正式执行的 `catdrama/V4.19`（T-09 已定：放 JSON）。
- **配置 / 运维要做 4 件**：网页放在哪里（决定要不要改跨域配置）、阿里云 OSS 跨域规则、支付宝网页支付的密钥配置、确认服务器能拿到用户真实 IP。

## 2. 架构变化

- **新增**：网页端工程 `catdrama-studio`（Flutter Web，T-01 已确认）。
- **新的跨端流程**（时序图见 `architecture.md` §4）：
  1. 密码注册 / 登录 / 重置（新接口）。
  2. 网页端新建账号的 IP 计数（Redis）。
  3. 电脑扫码充值：弹窗里放支付宝返回的二维码页面，网页轮询订单状态；到账以后端订单为准（与手机端一致）。
  4. 电脑端实名核身电签：网页把工猫签约地址显示成二维码，用户用手机扫码完成刷脸和签约，网页轮询核身状态（后端已有“浏览器回跳兜底”，不用改）。
- **新存储**：表 `user_password_credentials`；Redis 两类键（注册 IP 计数、密码错误次数 / 锁定）。字段见 `data-model.md`。
- **新三方**：无。支付宝、工猫、阿里云 OSS 都是现有的。

## 7. 后端方案

- **R-06 `X-OS-Type`**：`framework/context/AppCodeFilter.SUPPORTED_OS_TYPES` 改为 `ios、android、web、windows、mac`；`framework/config/OpenApiConfig` 的枚举同步。逐个看过用到这个头的地方：`ProductChannelPricingService`（只有 ios 特殊）、`GuestAccountService`（只允许 iOS）、几个后台任务只是透传——都不用改。
- **R-11 密码**（`core/auth`）：
  - 新 `PasswordAuthController`（`/api/auth/password/register|login|reset`），新 `PasswordAuthService`。
  - 密码加密用现有 `SecurityConfig.passwordEncoder()`（BCrypt），库里只存加密结果。
  - 注册顺序：校验密码格式 → 查手机号账号，已设密码则 `-1312`（先查再验码，避免白白消耗验证码）→ `SmsCodeService.verifyAndConsume` → 会新建账号时先过网页注册限制 → `UserService.findOrCreateByPhone` → 写密码表 → `InviteService.bindFromLogin` → `TokenService.issueTokens`。整个过程一个事务。
  - 登录：查账号（没有或没密码都返回 `-1310`，不区分，防止拿接口试探手机号是否注册）→ 查锁定 → 比对密码 → 失败计数（达 5 次锁 15 分钟）→ 成功清零并发凭证。错误计数在最后一次失败 24 小时后自动清零；触发锁定时计数同时清零（锁定结束后重新从 0 计）。冻结账号在注册、登录、重置里都返回“账号不可用”（`-401`）。
  - 重置：查账号（没有 `-1313`）→ 验码 → 写新密码 → 清锁定 → 发凭证。
- **R-24 网页注册限制**（`core/auth/WebRegistrationLimitService`）：
  - 只在 `X-OS-Type` 为 `web/windows/mac` 时生效；手机端不计数。
  - 计数时机：验证码通过后、真正建号前；用 Redis 有序集合 + Lua 脚本一步完成“删 30 天前的记录 → 数一数 → 不满 100 就记上这一条”，并发也不会超。
  - 建号事务回滚（后面任何一步失败）时删掉这条记录，保证“只算成功建号”（AC-24-4）。
  - Redis 不可用时按现有 `sms-risk-fail-closed`（默认 true）处理：拒绝并返回 `-1006`。
  - 接入两处：`AuthService.loginBySms`（新手机号自动建号）和 `PasswordAuthService.register`。
- **R-04 支付宝电脑支付**（`core/payment`）：
  - `PaymentInfoBuilder` 的 `ALIPAY_WEB` 分支：`AppContext.isDesktopClient()` 为 true 时走现有 `PaymentChannelService.pagePay` → `AlipayWebProvider.pagePay` → `AliPayUtil.pagePay`（加 `qr_pay_mode=4` 内嵌二维码、`qrcode_width=200`，`product_code=FAST_INSTANT_TRADE_PAY`），否则仍走 `wapPay`。参数名开发时按支付宝开放平台文档核对。
  - 订单详情 `GET /api/payments/orders/{orderNo}` 对待支付的 `alipay_web` 订单会主动查单（`PaymentOrderQueryService.detail` → `PaymentOrderStatusSyncService`，现有）；`PaymentOrderReconcileTask` 已包含 `alipay_web`，掉单能补。
  - 订单 15 分钟过期（`timeout_express=15m`）。15 分钟内二维码一直可用；满 15 分钟网页显示“二维码已失效”，“刷新二维码”= 同一套餐新下一单（AC-04-5，2026-11-16 修改）；“继续支付”未过期的订单仍调 `pay-params` 沿用原订单，已过期返回“支付订单已过期”。
- **B-10 漫剧分析与片段流程**（`app/catdrama/analysis`、`project`、`shot`）：
  - 剧本 → 分集（K-08）：剧本生成任务的结果解析多读每集素材清单，写入 `catdrama_episodes.asset_plan`；解析不到不让任务失败。

  - 确认素材并生成片段（K-02）：`DramaEpisodeStageService.confirmMaterials` 的图片检查范围改为本集全部素材（`asset_plan` 建立的绑定）；通过后在同一事务提交本集 `EPISODE_ANALYSIS` 任务（复用拆片段提示词 `drama.script.analyze.shots`），剧集进入 `SHOTS`；不新增接口、不新增父任务种类。提交由分析模块新方法 `DramaAnalysisService#startEpisodeShots` 完成，确认素材用 `ObjectProvider` 调它（分析模块已依赖作品模块，直接注入会循环依赖；照 `DramaProgressLog` 的现有写法）。
  - 检测结果（K-03、K-05、K-06）：`DramaAnalysisValidationException` 中能解析出片段的问题改为记录到结果里，不再让任务失败；解析不出片段的保持失败，但同时保存原因和原始返回，作品不再停在“分析失败”。
  - 单个片段描述（K-04）：新任务种类 `SHOT_DESCRIPTION`、新提示词 `drama.script.shot.description`，输入本片段原文、所在集剧本、素材注册表和制作参数；完成后经片段模块新方法 `DramaShotDescriptionWriter#replaceGenerated` 按片段版本 CAS 替换描述，版本变了就不覆盖。是否手改：片段 `analysis_problems.descriptionHash` 与当前描述不同即算手改。
  - 阶段（K-07）：`DramaEpisodeStageService` 的判断顺序改为 素材 → 片段 → 视频；`DramaWorkProcessService` 素材分析成功直接进入 `PRODUCE_EPISODES`。
  - `POST /api/drama/episodes/{id}/confirm-materials`：网页（W-08 当前集）和手机端（M11）都调用（K-02 选 A）。
- **B-13 重新分析本集素材（R-36，M16）**（`app/catdrama/project`、`analysis`、`generation`）：
  - 新接口 K-13 放在 `DramaEpisodeController`，受理在 `DramaProjectAnalysisService#reanalyzeEpisode`：和素材分析（K-01）共用快照组装和预审，区别是只分析这一集（`episodeIds = [本集]`、快照多 `reanalyzeEpisodeId`）、不拒绝“剧本没变”、不复用失败任务的冻结注册表；要求作品已在分集制作阶段，同一作品同时只能有一个素材分析在跑；受理时不调用作品流程的 `analysisAccepted`（作品流程不变）。
  - 执行沿用素材分析的步骤；`commitAssets` 对重新分析只登记本集要用的新素材（素材分析原来会登记全剧新素材），并对比前后本集关联，把新加的写进检查点 `assetReanalysis`。
  - 剧集阶段：`DramaEpisodeStageService#assetsBound` 对重新分析任务不做阶段迁移（原来素材分析成功会把全作品有效集都设成“素材”，已在片段 / 视频阶段的也会被改回），只刷新本集阶段摘要。作品流程监听（`DramaWorkProcessService`）按“不是作品当前任务就跳过”的现有逻辑不受影响，由测试确认。
  - 任务结果 K-14：`JobResult.assetReanalysis` 从检查点读出。
  - 已有素材按“已有身份”交给 AI，不改名称、描述、图片；本集已归档的关联不复活（`firstAnalysisBindings` 现有规则）。只改 `app/catdrama`，不改表。
- **事务、并发、幂等**：注册 / 重置都在一个数据库事务里；同一手机号同时注册两次，`users` 已有的手机号唯一约束和 `user_password_credentials.user_id` 唯一约束保证只有一个账号、一条密码记录（后到的那次返回 `-1312`）。
- **权益校验**：无新增；付费生成、积分、提现都沿用后端现有校验。
- **对其他 App 的影响**：`X-OS-Type` 多几个合法值，其他 App 不受影响；密码表在每个 App 的 schema 都建（空表），密码接口对其他 App 也可用但没人调用；电脑支付只在 `X-OS-Type` 是电脑值时生效，其他 App 的手机网页支付不变。 B-10 只改 `app/catdrama`，不影响其他 App。

## 8. 兼容与上线顺序

- **旧版本手机 App**：发的是 `ios/android`，所有返回都不变；不会碰到新错误码。
- **手机端与 B-10**：手机端本版一起做最小适配（M11、R-32）。开发期间：后端 B-10 先上测试环境、M11 还没做完时，测试环境上手机端的分镜流程会走不通。正式上线：后端和手机端新版要一起发布；已分析过的老作品保持原样，不迁移（D-40）。
- **上线顺序**：
  1. 后端（含数据库迁移，启动时 Flyway 自动跑）先上测试环境 → 网页端打开 `X-OS-Type` 开关联调 → 后端上正式。
  2. 运维配置：C-04 支付宝、C-03 OSS 跨域、C-02 部署位置、C-06 真实 IP（正式环境）。
  3. 网页端上正式。
- 网页端可以在后端改完之前先开发（假数据只给新接口）。

## 9. 风险

| 高风险领域 | 技术上怎么保证 |
|---|---|
| 钱：充值 | 到账只认后端订单状态 `PAID`（支付宝异步通知 + 主动查单 + 对账任务三重补偿，均为现有逻辑）；网页不根据二维码页面的跳转判断成功；金额只显示后端返回的 `amountCents`（分，人民币），不写死 |
| 钱：付费生成 | 先调报价接口再确认，提交时带报价结果；冻结 / 结算 / 退回全在后端（现有） |
| 钱：提现 | 只调用现有提现接口，重复点击用前端按钮锁 + 后端现有幂等；金额试算以后端 `withdrawal-quotes` 为准 |
| 账号：同一手机号只有一个账号 | 注册对已有账号只设密码；`users` 手机号唯一 + 密码表 `user_id` 唯一 |
| 账号：密码安全 | BCrypt；单账号 5 次锁 15 分钟；登录失败不区分“没账号 / 没密码”。**本版没做**按 IP 限制密码登录次数（撞库防护），如需要请告诉我加进后端计划 |
| 账号：注册风控能被绕过 | 风控依据是请求头 `X-OS-Type`，有人改成 `ios` 就不计数；只能防住普通刷号。真正的上限仍靠现有的短信发送 IP 限制（每 IP 每小时 60 条等）兜底 |
| 账号：共享 IP 误伤 | 上限 100 / 30 天；C-06 必须配对，否则所有人同一个 IP |
| 账号：切换账号后数据残留 | 退出 / 切换时清空全部内存状态和 localStorage 中的账号数据；迟到的旧账号响应丢弃 |
| 同步：手机和网页同时改同一作品 | 后端已有版本号冲突保护（`-560001` 内容已更新），网页收到后提示并重新拉取，不覆盖 |
| 数据安全：私有图片视频 | 每次通过 `/api/resources/{id}/access-url` 换签名地址，不长期保存 |
| 数据安全：浏览器里的登录凭证 | 存 localStorage（刷新页面不掉线）。风险是网页若被注入脚本可读到；Flutter Web 不拼接 HTML，注入面小。退出即删除 |
| 多设备：手机本机剪辑工程 | 网页看不到，也不提供剪辑入口（D-05） |
| 同步：手机端与新流程不一致 | 手机端本版最小适配（M11）；后端与手机端新版一起上线；开发期间测试环境上手机端分镜流程暂时走不通 |
| 数据：检测问题不判失败后，带问题的片段可能被拿去生成视频 | 后端现有规则不变：描述执行不了的片段 `canGenerate=false`，不能报价、不能扣费 |
| 数据：重新分析误改已有素材或剧集阶段（R-36） | 已有素材只作为“已有身份”交给 AI，登记时已有的直接跳过，不改名称、描述、图片；关联只补不删、归档不复活；重新分析任务不触发剧集阶段迁移、不进作品流程；只建本集要用的新素材 |
