## P5 执行开发计划（交给 ChatGPT / Codex，能同时打开后端和 App 两个仓库）

```
执行开发计划：{工作区}/{版本}/04-开发计划/开发计划.md，范围：{全部模块 / 指定的模块}。
后端仓库：{后端仓库路径}　App 仓库：{App 仓库路径}
规则：/Users/soul/work/MakeCodePlanWord/workflow/05-开发.md

总的做法：按总计划的顺序一个模块一个模块做，不用每个模块做完都等我。每个模块依次做三组任务：后端任务 → 前端任务 → 联调。全部模块做完后给我一份报告。

开始前：
1. 读两个仓库根目录的 AGENTS.md，再按"规范索引"读相关的规范文件。进入另一个仓库做事之前，先读那个仓库的。
2. 读总计划的模块清单：只做状态是"已审核"或"执行中"的模块。
3. 一次只读正在做的那一个模块计划，以及任务"契约"指向的 api.md、data-model.md 小节。

每个模块：
1. 复核开工条件。依赖的模块联调不是"通过"：本模块标"阻塞"，写明原因，跳到下一个模块。
2. 后端任务（B-xx）：只改后端仓库，不改 App。按 api.md 的样例做接口测试，返回要和样例一致，并核对数据库里的数据。
3. 设计核对（做前端任务之前）：实际打开 §4 每一行的 Figma 节点或设计图；对照 AC 和 §8 验收路径，找出 §4 没列的界面或状态。有缺失、打不开、对不上的：本模块的前端任务不做，标"阻塞"，把"设计缺失清单"写进报告，继续下一个模块。
4. 前端任务（F-xx）：只改 App 仓库，不改后端。数据只用 api.md 的样例做成的假数据，放在计划指定的目录，通过计划指定的开关接入，不写进业务代码。每个界面照着 §4 的设计依据做；§4 没有的界面、状态、弹框、提示、组件、图标一律不做，包括临时、占位、简单版。在真实运行的 App 里与 §4 的设计图同视口并排截图，存 {工作区}/{版本}/05-测试/evidence/{模块}/。
5. 联调（J-01）：App 关掉假数据开关，连真实后端，按 §8 验收路径从头走一遍，每步截图。出了问题先判断属于谁，再修：
   - 后端不符合 api.md：回后端仓库改；
   - 前端不符合 api.md：回 App 仓库改；
   - api.md 没规定或规定错了：不改代码，记进问题清单。
   不为了让联调通过而两边一起改，不改 api.md 来迁就代码。
   同一个问题最多修 3 次。3 次仍未解决：联调标"有问题"，模块标"阻塞"，把现象、证据、三次各做了什么、判断的原因、属于哪一端写进总计划的"问题清单"，然后继续下一个模块，不要停下来等我。
6. 联调通过：删除本模块的假数据、开关分支和相关代码，搜索确认没有残留；联调标"通过"，模块状态改"待验收"。

每个任务：
- 开始前把任务状态改为"进行中"，完成后改为"完成"，"结果"最多两行：做了什么、提交号；证据路径。
- 只改任务里列出的文件。做某一端的任务时发现另一端或接口文档有问题：写进任务"结果"，不改，留到联调处理。
- 跑任务里的验证命令和 AGENTS.md 规定的验证命令。
- 接口改动总览以外的接口、表结构、流程推进方式一律不动；不把"用户确认"的步骤做成自动。
- 不要修改 {工作区}/当前产品文档/，以及 {工作区}/{版本}/ 下的 01-产品、02-设计、03-技术规划；不要改模块计划的 §4。不在对话里改产品规则。
- 发现值得记录的经验写进报告，不要直接往 AGENTS.md 或规范里加条目。

只有这几种情况立即停下来问我，其他问题一律记下来继续：
- 需要动接口改动总览以外的接口或表结构；
- 涉及钱、权限、删除数据，而计划没有写；
- 计划写的文件或仓库不存在，整份计划无法执行。

全部模块做完后给我一份报告，然后停下，不要自己进入统一联调：
1. 接口改动总览的实际结果，放在最前面：和总计划最上面的总览逐行对比，一致的标“一致”，多出来的行逐条说明出处，说明不了的撤回；
2. 每个模块的后端、前端、联调结果；
3. 问题清单：每条写清哪个模块、现象、证据、试过什么、判断的原因、建议怎么改；
4. 假数据：哪些模块已经删除，哪些因为联调有问题还留着；
5. 被阻塞的模块和原因（含设计缺失清单）。
```
