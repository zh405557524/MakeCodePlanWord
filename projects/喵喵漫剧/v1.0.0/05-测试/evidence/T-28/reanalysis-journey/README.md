## 实际范围

两端各用同一隔离账号、同一作品，从最终确认剧本、素材分析、两张图片/自动作品分类与应用、一个有声视频，进入本机剪辑、文字、主动字幕/校对、原生导出、系统相册及两项成长领取。然后在真实本集剧本页面保存/分析/核对/确认四次，并明确找回原镜头。HTTP使用真实Dio/Servlet/JWT/PostgreSQL和公共资源账务；AI/ASR/私有对象服务的外部边界受控，不代表真实Provider/OSS或物理设备验收。

| 操作 | 新增/保留/移出 | 实际数据检查 |
|---|---|---|
| 开头插入钟声剧情 | 1/1/0 | 原shotId/视频保留，新开场无旧视频；取消后重开同候选，不重复分析 |
| 改写原剧情 | 1/1/1 | 改写段新建，旧镜头和旧视频留在移出历史 |
| 还原原文 | 1/1/1 | 新分析不自动借回旧ID/视频；用户明确恢复后找回原shotId/videoVersionId |
| 原封重排 | 0/2/0 | 两个镜头ID均保持，只改变制作列表顺序 |

每步比对完整Hive工程（含head/undo/redo/来源/选择等）序列化结果；全程与原快照相同。原MP4摘要不变，相册副本与原文件一致；再次从有效作品准备入口打开同一工程，保留原文字和已校对字幕。没有后台时间轴、成片上传或新生图/视频请求。

每个账号最初为测试资金10000积分，原两图240＋视频1200结算后8560、两项成长后8580，冻结0；四次分析/镜头恢复不新增费用。后台核对20个文本步骤、8次复用已有素材注册，只有4图/2视频/2ASR的原调用。
