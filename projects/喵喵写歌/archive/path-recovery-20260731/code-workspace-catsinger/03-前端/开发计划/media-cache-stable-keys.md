# CHG-0025 媒体稳定缓存键与单请求加载开发计划

## 范围

- 只修改 Catsinger Flutter App 的媒体缓存、歌曲播放、统一图片组件和稳定业务 id 调用点。
- 不修改后端接口、数据库、对象存储配置、Android/iOS 原生配置或本地缓存容量选项。
- 目标是减少临时签名 URL 变化造成的重复下载，并消除首次播放/展示的双请求。

## 缓存契约

1. 下载 URL 与缓存身份分离；业务键按当前 App 环境隔离。
2. 歌曲主音频使用 `song:{workId}:audio-primary`，歌曲封面使用 `song:{workId}:cover`。
3. 首页标签、歌曲案例、专辑和音色资源使用各自稳定业务 id；没有稳定 id 的旧入口继续回退 URL。
4. 旧 URL 键缓存账本不迁移、不强制清空，继续参与容量统计和 LRU 淘汰。
5. 封面重新生成属于同 id 内容替换，成功后必须显式删除封面业务键及 Flutter 已解码图片。

## 请求策略

1. 主歌曲缓存命中时直接播放本地文件。
2. 主歌曲首次未命中时只下载一次，完成后播放该本地文件，不再同时启动 URL 流式播放。
3. 统一图片组件在缓存服务可用时只由缓存层下载一次，落盘后展示 `FileImage`。
4. 缓存服务未初始化时保留单独网络展示兜底，但不会同时启动缓存下载。

## 验证

- 同一歌曲 id 使用两个完全不同的临时音频 URL，只产生一次真实缓存下载。
- 同一歌曲 id 使用两个完全不同的临时封面 URL，只产生一次真实缓存下载。
- 主播放链路更换签名 URL 后继续复用同一业务键本地文件。
- 删除封面业务键后再次读取会重新下载。
- `dart analyze lib`、相关 `flutter test` 和 `git diff --check` 通过。

## 验证结果

- 稳定媒体键测试、主播放单请求测试、隐私前迷你播放器测试和首页歌曲列表 3 项测试通过。
- `dart analyze lib` 无问题。
- 全工程 `flutter analyze` 仅保留既有测试重复 key 警告。
- 既有歌曲作品/音色 Widget 用例中的乱码文本断言仍可独立复现，不属于本变更。

## CHG-0026 服务收口

- 删除 `MediaCacheService`，公开缓存能力、稳定业务键、容量设置与私有资源本地化统一迁入 `ResourceService`。
- 缓存落盘实现改为 `resource_cache.dart` 私有组件，不再由业务层直接注册或查找。
- 隐私同意前 `ResourceService` 仅提供未启用状态，统一图片组件继续回退网络展示；同意后初始化缓存，撤回后释放内存图片并停用缓存。
- 保留原缓存目录、账本键和容量配置键，不迁移或清空现有用户缓存。
