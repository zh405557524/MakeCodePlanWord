# UI 处理任务

## 一、设计输入来源

优先级：

1. 版本 `scope.md`「设计来源」表指定的设计稿（Figma / 外部稿 / AI 参考图）
2. 文档目录的 `design/README.md`（设计系统、切图位置）
3. 需求：版本 `changes.md` 与 文档目录的 `product/` 基线
4. 参考图
5. 现有页面风格（设计来源为「C 不出稿」时以此为准）

不要只凭单张截图猜交互。
动态数值的业务真源仍是服务端模型/后台配置或任务响应；Figma 示例数字不覆盖需求文档中已确认的业务规则。

### 动态数值对稿

- 价格、积分、次数、时长、容量、额度、进度和有效期等按接口返回展示，不把设计稿中的示例数字硬编码进 View、Controller 或校验逻辑。
- 对稿检查数值容器、单位、换行/溢出、加载/空/错误和刷新状态；实际值与示例不同不算 UI 返工，也不要求修改 Figma。
- 固定文案或业务动作与已确认规则不一致时，以产品规则实现并记录差异；没有用户明确授权，不编辑 Figma 文件。

---

## 二、实现顺序

1. 拆页面主区块
2. 判断组件复用
3. 建立页面状态
4. 落主题与样式
5. 补齐交互反馈

---

## 三、组件复用优先级

1. `lib/widgets/`
2. `lib/components/`
3. 当前模块 `widgets/`
4. 新建局部组件

---

## 四、适配规则

若工程启用 `flutter_screenutil`，则统一使用：

- `.w`
- `.h`
- `.sp`
- `.r`

不要在启用适配方案后继续大量使用裸尺寸。

---

## 五、主题规则

- 优先使用 `theme.dart`
- 重复使用的颜色、间距、字号不要散落成魔法数字
- 若页面形成稳定样式令牌，应抽回主题或工具层

---

## 六、状态完整性

UI 实现默认至少考虑：

- `loading`
- `empty`
- `error`
- `disabled`
- `submitting`
- `not_found`

不要只做 happy path。

---

## 七、资源使用

- 资源路径优先通过 `utils/assets.dart` 统一索引
- 不在业务代码中大量硬编码资源路径
- 复杂图形优先资源化或组件化

---

## 八、View 与 Controller 协作

UI 改动时同步检查 Controller：

- 是否需要新增状态字段
- 是否需要新增交互方法
- 是否需要补空状态/错误态
- 是否需要补路由返回逻辑

不要只在 View 层打补丁。

---

## 九、对稿清单

- 背景层次
- 标题与正文层级
- 区块顺序
- 留白与间距
- 卡片圆角、边框、阴影
- 主次按钮层级
- 空状态/错误态/加载态

---

## 十、完成后的检查

- 页面区块齐全
- 组件复用合理
- 适配方式一致
- 状态完整
- 与 Controller 联动正确
- 无明显溢出
- `flutter analyze` 通过
